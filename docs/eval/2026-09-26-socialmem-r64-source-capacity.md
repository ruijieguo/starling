# SocialMemBench R6.4：来源容量20的真实QA评测

**观察到得分改善，但可靠性明显不足，暂不晋升。** grounded_memory_v1从41/133升至48/133（36.09%），净增7题、5.26个百分点；legacy保持37/133。Q8状态变化题贡献了6题净增，是本轮主要收益。grounded正常率却从91.73%降至84.96%，网络区间下界为0，尚不能确认稳定提升。高分目标仍未达到。

一个可复核的时间范围案例是Q8_cf13s2c3：问句明确要求Sessions 2、3中Dan对pub nights的改变，但k20的20条来源中14条来自其它session。关键的饮酒量回应和次日自述变更仍未呈现，BM25分别排136、140；只保留了后期行为锚点。该题的本轮QA实际因截断计错；上述遗漏是独立检索诊断，不能把技术失败直接归因为它。应检验问题时间范围、同事件回应和变化界点的联合选择，而非只增加全局早晚状态。该计数使用事后阿拉伯数字Session正则，仅检出4道显式题，不能视为全套时间理解能力评测或将所有时间提及当作硬过滤条件。完整证据见工作目录`remaining-anchor-diagnosis.json`，未进入当前检索或回答输入。

逐题改善/退步、原答案、参考及上下文保存在工作目录的`diagnosis.json`；主分数不作人工修正。

## 典型改善、退步与评分边界

以下案例均保持原始裁判标签，不用于估计总体裁判误判率。

1. **完整变化链带来改善：Q8_a6b7c8d9。** Kwame装备准备题的锚点从0/4提高到3/4。k10回答认为没有装备准备证据；k20新增忘带雨具、借Nadia装备产生负担、手机清单承诺与下一次实际带齐装备的来源，回答串起触发和执行，正常判错转为正常判对。
2. **补齐比较对象和反馈机制：Q8_d7e8f9a002。** Simone釉色题锚点1/2→2/2。k10只看到中性色“30”，以含糊的外部反馈解释选择；k20补入Instagram青绿色400赞对中性色30赞，明确外部认可如何把先前不满变成Session 4的决定，正常判错转为正常判对。
3. **有证据仍遗漏关键关系角色：Q7_b1c2d3e402。** 两臂都命中唯一公开锚点。k10明确提到Fatima作为激励者或教练的作用；k20概括为长期搭档和“相互信任”，虽引用影响报名和了解配速的原话，却没有明确较有经验一方的指导角色。原判对转为判错，说明通用亲密/信任描述不能替代问题要求的关系区别。
4. **参考答案裁判存在可见性争议：Q8_b1c2d3e406。** 两臂锚点均2/2，均回答Chloe退出比赛、此前淡化伤情、Fatima评估促成改变。k20改引用Session 4的轻视伤情原话并增加到场加油；这些内容已核实真实存在于选中来源。裁判只见参考答案，将与参考Session 1不同的引文位置等视为不等价线索。该样本提示评分可见性限制，也可能受问题时间范围解读影响；保留原判错，不进行人工改分。

## 下一轮顺序与验收边界

1. **先独立解决输出可靠性。** 固定k20上下文、模型与原评分，预先设计512/1024输出容量的同期比较或经验证的C++回答组织方案，完整评测133题；不能只补答截断题后拼成新成绩。容量仍通过现有C++适配器配置，Python不复制语义逻辑。既往733题容量实验收益有限，本轮的新证据是k20下截断增至20次，故必须重新验证，不预设扩容必然改善语义准确率，也不复用曾退步的过度紧凑策略。
2. **再补C++互动与变化证据选择。** 为同事件前态、触发、回应、后续执行及人物归属设计通用合同；问句明确的时间范围应参与排序，但不能把所有时间提及直接当作硬过滤条件。先用非benchmark专属文本写正反例，再实现同库消融；不使用gold锚点或参考答案选来源。
3. **继续约束关系推断强度。** 对指导/受指导、同伴、单次帮助和长期信任作证据角色区分。Q7仍弱且legacy退步，应优先验证具体互动机制，不能仅增加谓词名称或把被拒候选全部放行。
4. **保留独立评分审计。** 对来源可见性争议做单列复核，继续使用原裁判作为主指标。新的能力或输出配置达到完整门槛后，再进行同期对照及更广范围验证，不把开发集调优结果当成生产或保留集效果。

后续继续遵循中文设计→测试反例→C++核心或已有配置实现→评测分析，并同步所有设计文档。本轮没有实施上述下一阶段改动。
