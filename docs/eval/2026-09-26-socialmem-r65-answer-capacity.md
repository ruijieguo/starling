# SocialMemBench R6.5：固定k20的同期512/1024输出容量评测

## 结论与范围

固定八库、133题开发集、k20来源、grounded_memory_v1策略及qwen3.8-27b，本轮仅改变回答输出上限。512和1024均为本轮新生成的133个答案，控制来自同期交错运行；未补答拼接、未改变评分、未扩大检索或新增embedding。

|指标|512控制|1024候选|
|---|---:|---:|
|正确|44/133（33.08%）|50/133（37.59%）|
|正常终态|121/133（90.98%）|131/133（98.50%）|
|回答截断|12|0|

完整133分母净增+6题，+4.51个百分点；六网络聚类bootstrap的95%区间为[-1.01, 9.56]个百分点。技术失败均计错。扩展开发验证门槛未通过；本轮不自动晋升、不修改产品默认。

**本轮确认了输出可靠性改善，但尚未证明稳定的准确率提升，更未补齐社会关系和变化机制理解。** 未过门槛有三个明确原因：主增益4.51个百分点低于5个百分点；主区间下界小于0；512控制正常率90.98%低于95%。共同正常子集的正区间不能替代这些主验收条件。

该实验是经过多轮调优的开发集，同期比较也不能消除单次生成与裁判噪声。六网络、100000次bootstrap、既有seed20260925；区间条件于本次固定评分，不是多次独立LLM运行的不确定性区间。结果不代表全量SocialMemBench、保留集或生产能力。

## 配对变化与输出可靠性

四格：两臂都对40题、仅512对4题、仅1024对10题、两臂都错79题。共同正常119题，正确42→48，净增+6；共同正常仅作诊断，不替代主分数。

共同正常95%网络区间：[0.80, 9.70]个百分点。

|512状态→1024状态|题数|
|---|---:|
|正确→正确|40|
|正确→正常但判错|2|
|正确→技术失败|2|
|正常但判错→正确|8|
|正常但判错→正常但判错|69|
|技术失败→正确|2|
|技术失败→正常但判错|10|

512失败全部是回答到达512-token上限而截断，共12次。1024的133个回答全部正常停止，最终仍有2题因裁判请求超时计错；超时没有重试。

12道控制截断题在候选臂全部恢复正常，但只有2道判对，其余10道正常判错；与此同时，2道控制原本答对的题在候选臂裁判超时。因此，涉及技术状态变化的题目对本轮净正确数贡献恰为0，净增6题全部来自共同正常题目中的8个改善、2个退步。不能将这6题直接归因于消除截断。

12道恢复题中，8道候选答案确实超过512 tokens，4道仍不超过512；两臂是独立生成，未使用相同采样轨迹重放。这里证明的是本次1024配置的实际可用性，而不是“如果把同一段被截断输出接着生成，必然补对12题”。

同一题两臂的提示词及上下文字节全部一致，也与R6.4同k20的grounded输入一致。R6.4的48/133、113正常、18截断仅为历史背景，不混入本轮主对照。相同裁判prompt重复组15，翻转组2；不能据此推断总体裁判误差率。

两组评分翻转为Q1_b1c2d3e401和Q5_b1c2d3e402：答案及裁判提示词完全相同，两次分别被判错、判对，方向均有利于1024。这2题属于明确可观察的裁判波动，不能作为容量带来语义改善的证据。保留原始主分数，不人工改分，也不将其它差异自动解释为真实能力变化。历史相同512配置的48/133在本轮变为44/133，同样提示单次运行的不稳定性。

## 典型案例与剩余能力短板

1. **较长回答获得完整得分：Q7_d7e8f9a003。** 512输出截断，1024答案为552 tokens，恢复了Reuben与Callum多年技术分歧、关键反馈、持续关注项目等关系依据，原判错变为判对。该例支持保留充足输出容量，但两次为独立生成，不声称候选是原输出的精确续写。
2. **恢复输出仍缺关键事件机制：Q8_cf13s2c3。** 1024正常回答仍把Dan改变pub nights习惯的触发解释为“问答活动很糟”，并把另一个邀约的拒绝推为主动回避社交。选中上下文只有1/3公开锚点，缺少饮酒量、持续宿醉及本人“改变看法”的直接自述；20条来源中14条不在问句要求的Sessions 2、3。相比上一轮该题截断，本轮已能直接观察正常答案的错误机制。证据遗漏与额外因果推断同时存在，不能只继续扩容。
3. **关键证据已呈现，仍回答了另一段关系历史：Q7_b1c2d301。** 原文明确含有Marcus和Greg在Covid期间共同维持周六跑步的叙述，公开锚点1/1；候选却围绕2017年创办和Greg招募首批成员作答，漏掉共同维持俱乐部的关系意义。这是答案未按问题选用关键证据，不能归为检索完全未召回。
4. **归属与推断强度仍需约束：Q7_fm7s5c1。** 1024回答完整且锚点1/1，却大量使用“相互支持、亲密伙伴”等泛化叙述；“flights are genuinely a lot”在选中来源中是Imogen的发言，回答却与Kofi的真实跨洋旅行自述并列归给Kofi，并推导出较强的心理安全关系。需要保留谁说了什么、单向照护负担和兄妹角色，不能仅靠更长回答堆叠关系形容词。
5. **正常答案退步需谨慎解读：Q8_e6f7a8c0。** 两臂均全锚点3/3，均提到Leo拉伤、此前忽视拉伸及后续执行；候选额外对比其它训练纪律，并把Nadia当下提问解释为此前已经知情。原判对变为判错。这是时间归属与推断强度的检查点，也受裁判波动影响；本报告保留原判，不声称单一样本证明根因。

所有改善、退步及未改善题的原答案、参考和选中上下文在工作目录diagnosis.json中。上述案例仅作可复核诊断，不修改主标签；没有将裁判长推理正文作为新的事实来源。

## 下一轮优化方案与执行边界

1. **输出配置作为实验控制。** 下一轮C++检索消融的两臂统一使用1024，降低截断对证据选择评测的干扰；它是后续实验条件，不是产品默认晋升。本轮没有增加到更大容量的证据需求，候选实际最大输出为779 tokens。
2. **C++事件与互动证据选择。** 给单人物变化问题提供受预算约束的触发/回应候选；按人物、主题、同事件和明确时间范围选择前态与后态，保留actor/speaker、租户、会话连续性与有效声明合同。当前只读统计显示Q8全部40题触发时间线，但仅7题启用互动槽，状态链缺27个角色；这是候选机制线索，尚未通过新策略消融验证。
3. **C++回答证据组织与角色合同。** 让直接回答问题的证据先于泛化人物历史，区分共同创办、共同维持、指导/受指导、亲属照护及单次帮助；保留事实归属与有限推断的边界。先用非benchmark专名和文本写正反例，再实现核心逻辑，Python继续只做binding与评测编排。
4. **先证明上下文变化，再真实比较。** 通用测试覆盖单人物变化由他人触发、多主题早晚状态竞争、无关邻接、未知位置、跨会话、第三人评价、低k/字节预算、无变化题保持原行为。对同库冻结消融核验有效证据变化后，再完整133题同期评测；公开锚点和参考只作事后诊断，不参与排序。
5. **评分审计保持独立。** 原评分仍作主指标，重复相同输入翻转单列报告。后续若尝试改变裁判thinking、可见证据或提示词，必须作为独立评分研究，不能与核心能力增益混合比较。

本轮完成的是输出容量实验，没有实现上述下一阶段C++能力改动。静态线索与通用反例清单位于工作目录next-cycle-hypotheses.md，下一轮仍遵循中文设计→测试→实现→评测分析。
