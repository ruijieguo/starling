# SocialMemBench R4.0 双臂评测与能力短板诊断

日期：2026-09-22。状态：实现、回归、真实请求、终态核验和封存均完成。此报告为 57 题开发集诊断，非全量基准成绩。基础模型及裁判均为 `qwen3.8-27b`。

## 1. 结论与决策

R4.0 两臂均正确 **19/57（33.33%）**，历史 R3.5 为 **16/57（28.07%）**，净增 3 题、5.26 个百分点。两臂相对历史的网络重采样区间均跨零，没有达到预注册的“共同正常题净增至少 5、区间下界大于 0”条件，不能声称稳健或大幅提升。

原生回答臂相比检索臂新增正确 3 题、退步 3 题，净收益为零；新增 3 次输出截断，回答与裁判总 token 增加约 68.2%。因此 `grounded_memory_v1` 不作为默认答案策略，`evidence_profile_v2` 也保持实验状态。工程修复与实验质量结论分别保留，不把测试通过当作准确率提升。

最明确的能力短板是**按人物、话题和阶段组织证据的能力不足**：Q7 原话锚点覆盖改善，Q8 覆盖显著下降；通用时间/互动配额不能稳定找到与问题有关的变化链。谓词丰富度仍需要后续评估，但本轮失败并不能只归因于谓词不足，原话已经入库却未被选入上下文是直接可复现的损失。

## 4. 来源覆盖与根因

本轮严格以公开锚点的 `(speaker_display_name, turn_id)` 与 `source_refs` 的 `(speaker, turn_id)` 匹配。父结果重新计算为 53/104，恰与此前子串估计相同，但计算依据不同，不能把旧估计倒称为此前已验证的精确召回率。

| 题型 | 锚点数 | R3.5 原话命中 | R4 原话命中 |
|---|---:|---:|---:|
| Q1 | 17 | 10 | 12 |
| Q2 | 5 | 3 | 1 |
| Q3 | 7 | 2 | 2 |
| Q4 | 9 | 6 | 5 |
| Q5 | 10 | 3 | 6 |
| Q6 | 6 | 1 | 0 |
| Q7 | 13 | 2 | 7 |
| Q8 | 37 | 26 | 13 |
| 合计 | 104 | 53（50.96%） | 46（44.23%） |

另读取已召回声明的 `semantic_claim_json.source_turn`，仅计精确出处回指：父有 7 个“无原话、仅声明回指”锚点，R4 有 9 个；原话与声明回指并集为 60/104 → 55/104。回指不证明该声明保留了完整语义，因此不能把并集当作答案要点覆盖率。

所有 57 题最终都是 7 条 SOURCE + 3 条声明，上下文字节最小 1275、平均约 2750、最大 4353，均低于 8000 上限。当前证据损失主要发生在候选排序和条数分配，未由总字节容量耗尽触发。

### 4.1 时间覆盖没有绑定目标人物及相关话题

`Q8_r3b8c9d0` 问 Cass 如何逐渐影响路线选择。新策略覆盖了 5 个会话，profile 没有缺口，但精确锚点从 2/3 变为 0/3。所选 7 条原话中只有 2 条由 Cass 发言，其余是提及 Cass 的他人发言。结果缺失初期偏好和后期主动提供鸟类调查数据的关键环节，两臂均给出不完整的演化解释。

这暴露了会话覆盖计数的局限：覆盖多个日期不等于覆盖一个人物在同一话题上的前态、触发和后态。`semantic_verified=false` 的限制是必要的，空 gaps 也不能解释成充分证据。

### 4.2 关系触发把人与事物的关系混作人际互动

`Q8_v4s3c2` 问 Preet 与实体唱片收藏的关系变化，因问题含 relationship 触发互动车道。原话锚点从 3/3 降到 1/3，遗漏“第一次更想拥有实体而非串流”的转折。原生回答又因输出截断失败。这里需要人物与话题角色区分，单靠关系词并不能判断应保留两人互动。

### 4.3 社会关系解释有局部改善，但覆盖提升尚不能稳定转化为正确答案

`Q7_r3a7b8c9` 关于 Bev 与 Marcus，原话锚点从 0/2 提升到 2/2。父回答缺少直接互动而拒答，新检索提供了 Bev 关心膝伤、替 Marcus 预判路线偏好的证据；原生回答被裁判判对，旧提示回答仍被判错。这说明组合证据与社会推断存在改善空间，但也提醒单次裁判的判定边界需要独立检查，不应手动改分。

Q7 整体覆盖从 2/13 到 7/13，检索臂正确数仍只有 1/8；原生回答才达到 3/8。选中引用只是必要环节，关系对齐、隐含动机与证据组织仍然不足。

### 4.4 长回答占用预算而未增加整体正确数

`Q3_c0s3c2`、`Q3_ph9s1c1`、`Q8_v4s3c2` 均为原生回答 `completion_truncated`，没有对失败输出继续裁判。新提示与证据包引导较长的分段解释和引用，导致请求和输出明显增加。固定 512 上限下应优先输出问题要求的要点，并限制冗余重述；单纯加大 token 上限不是本轮已证明的改进。

## 5. 技术、成本与评分限制

57 次检索均正常，无降级、解析失败、重试或未知收费。114 个回答终态中 111 正常、3 截断；85 次裁判均成功。实际 544 次 HTTP：查询 embedding 345，回答 114，裁判 85；账本预留和未知收费均为 0，低于 600 硬上限，剩余 56 次没有继续使用。

| 用量 | 检索臂 | 原生回答臂 |
|---|---:|---:|
| 回答输入 token | 62164 | 121542 |
| 回答输出 token | 4735 | 12584 |
| 回答总 token | 66899 | 134126 |
| 裁判总 token | 43301 | 51214 |
| 回答及裁判合计 | 110200 | 185340 |

这些是服务响应实测用量，不含 embedding token；未按未经核验的价格换算金额。原生回答总 token 约为检索臂的两倍，答案加裁判合计增加 68.2%，而正确数相同。

本轮沿用父裁判构造方式，回答显式关闭 thinking，裁判未显式设置 thinking。85 个裁判响应均含 reasoning_content，报告的 reasoning token 共 57074。因此请求中的 `judge_max_tokens=64` 不能被解释为实际总生成量只有 64；用量必须按原始响应审计。此轮没有改裁判协议，未来若显式更改 thinking 必须建立新的可比较基线。

查询 embedding 接口暴露原生 HTTP 次数，未保存其原始响应体；回答与裁判保留原生 HTTP 响应。345 次查询 embedding 来自按 holder 重复查询，后续可在 C++ 对同一问题复用向量降低成本，但需要验证隔离和一致性，不能先行假定得分不变。

## 7. 下一轮优化顺序

1. **先修人物与话题的证据选择。** 时间候选按目标人物、主题和会话组织，优先保留其自身的相关前态和后态；第三方补充独立计数。通过非基准人物夹具验证“日期覆盖齐全但主体证据缺失”的反例。
2. **约束互动触发和多样性配额。** 区分人际关系与人与事物的关系；主题相关性不足时不为日期或邻句硬占名额。测试无关第三方密集发言、关系对象是物品、长姓名及多人比较等边界。规则不得读取题型编号或答案。
3. **压缩原生回答。** 保留必要的证据约束和主体归属，以简短要点覆盖问题，减少重复引用；多成员问题逐人给出短结论。继续保持单次回答，先验证固定 512 上限下无截断，再与旧提示配对。
4. **补齐结构化能力的具体缺口。** 在已选原话充分但仍失败的样本上，区分缺少谓词、事件状态链、他人信念归属、间接回应或反事实信息；建立独立 C++ 能力测试后再扩展抽取合同，避免盲目加谓词表。
5. **扩大验证前先完成小范围回归。** 57 题已反复用于开发，应保留结果诊断属性。新方案先文档和测试，再冻结预算、完整写入范围及新的保留网络；不得只挑 Q7 的正向结果宣称通用提升，也不得把剩余 HTTP 额度自动用于额外实验。

以上为下一轮设计建议，本轮封存代码和评测结果保持不变；当前不满足生产晋升条件。
