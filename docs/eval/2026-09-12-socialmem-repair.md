# SocialMemBench 可空主题与情绪误拒修复

**状态：** 本轮文档、失败测试、C++ 修复、全套工程测试、离线与真实诊断核验均完成。真实运行 `verified / complete_with_errors`，质量门槛未通过，生产开关保持关闭。逐项数据见 [分析归档](2026-09-12-socialmem-repair-analysis.json)。

## 问题与修复

上一轮 `build/socialmem_20260912_optimization_real_final/` 共 16 个技术失败。14 个报告主题字段错误，但逐条检查原始响应后可区分为 10 个有效 null 和 4 个无效空字符串；另外 1 个是谓词越界，1 个是准入原因枚举非法。不能将 14 个主题错误都解释为 null 误拒。

原 C++ 解析器在语义校验中允许缺省或 null 主题，在组装证据时却要求已有主题必须是非空字符串，因此整批有效候选被清空。现将可空主题的形状校验统一前移到整批预检：null 原样保留，空白字符串和错误类型仍拒绝；Bus 写入与检索共用原生规则。新增回归同时覆盖语义无效行不能掩盖 schema 错误。

原关系检查将整行出现“觉得/感觉”直接视为认知命题，误拒“想到要离开团队，我觉得很难过”。现在按候选中的明确认知补语收窄确定性检查，模糊语义仍交给 C++ 调用的完整来源准入；不引入 Python 语义补丁。归属、否定、条件、时间和主题同源性契约保持。此次生产提示未修改，后续真实得分仍受模型波动影响，不能将全部变化归因于代码。
