## 设计、失败测试与实现

中文设计先同步到优化设计、计划、总设计、抽取/配置/自由生成专项及两份技术报告。C++ 新增 `OpenAIAdapter::Config::json_object_output`，默认关闭；只对 `extract()` 发送 `response_format: {"type":"json_object"}` 并保留 `choices[0].message.content` 原文。普通 `generate()` 与 `generate_stream()` 不携带该参数。Python 仅映射配置和实验参数；旧数组抽取使用默认实例，诊断只为对象信封抽取和准入显式开启。

配置缺失与评测 CLI 缺失分别记录于 `build/json_mode_config_red.log`、`build/json_mode_cpp_red.log`、`build/json_mode_cli_red.log`。真实本地 HTTP 回归的 RED 记录于 `build/json_mode_http_red.log`：未发送参数、模型原文中的推理标记被清洗均复现。实现后请求、原文保真、普通生成隔离、流式隔离与 HTTP 400 拒绝不降级等测试通过。没有公开仅供测试使用的请求构造函数，也没有将配置值包装成服务端支持声明。

独立审查另复现：中文尾随解释产生的 JSON 解析错误可能截断 UTF-8 token，导致整个回执不能编码。先补 C++ 抽取/准入两条失败测试及 Python 真实原生归档测试，再由 C++ 将底层解析异常转换为稳定 `envelope_failure` 详情；原文不变，格式错误继续计入严格分母。RED/GREEN 日志为 `build/json_mode_receipt_{cpp,py}_{red,green}.log`。本修复防止实验遇到合法 UTF-8 中文违规输出时中断，不将违规输出变成成功。

## 服务端探测

`build/socialmem_20260912_json_mode_probe/result.json` 保存一次最小实调用。提示仅要求返回 `{"ok":true}`，原生传输 `ok=true`，但响应为带 `json` Markdown 围栏的对象；裸 JSON 检查失败。结论是当前端点接受参数，不能证明实际强制 JSON 格式，更不能证明 schema/枚举保障。该原文不清洗，不能记作 JSON mode 约束成功。
