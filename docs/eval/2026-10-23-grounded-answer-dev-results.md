# 先引用、后作答 开发评估结果

预注册：`2026-10-23-grounded-answer-dev-prereg.md`（冻结于 `0c45e9d`，修订 1 于 `f53378b`，均在看结果之前）。
数据：已烧的 BEAM-500K 会话 7–35，580 题。这是开发评估，不是验收。

## 1. 结论

**按冻结判据：G1 不过、G2 过 →「无害但无效，不上 BEAM-1M」。**

| | B（现行） | G（先引用后作答） | 判据 |
|---|---|---|---|
| D1 弃答错误（58） | 10 | **8**（修好 3、弄坏 1） | G1：≤ 5 ✗ |
| D2 可答均分（522） | 0.602 | **0.643**，配对差 **+0.042 [+0.017, +0.066]** | G2：下界 ≥ −0.03 ✓ |
| D3 可答低分率差 | | −3.1pp [−6.3, +0.2] | 描述性 |
| D4 格式遵从 | | 96.9% | 描述性 |

运行健康：580/580、context 与 prompt 逐字节一致性 0 失败、缺判 0。token 8.74e6（超支，修订 1 追认）。

**可答题不降反升**——这与 v1（前提核验，−0.087）方向相反，说明「核对合进作答」确实避开了 v1 的误伤机制。
但弃答题只修好 2 题净，远未到 ≤ 5 的门槛。

## 2. 评测设置缺陷：作答长度上限

**作答模型 `max_tokens=2048` 对 G 臂不够**：证据块本身要占输出（summarization 题证据块中位 3.4K 字符），
G 臂 **32/580 题撞上 2048 上限**（B 臂为 0）：

- **18 题证据块没写完就截断**：没有闭合标签，`strip_evidence_block` 按设计原样返回——用户（与裁判）看到的是
  半截证据块，没有作答。这 18 题就是全部的「格式不遵从」。
- **14 题证据块写完、但作答被截断**。

| 可答题 | n | B | G | 差 |
|---|---|---|---|---|
| 撞上限 | 29 | 0.600 | 0.424 | **−0.175** |
| 未撞上限 | 493 | 0.602 | 0.656 | **+0.054** |

summarization 从 0.528 降到 0.357，是唯一明显受伤的能力，撞上限的 14 题占了它的四分之一。

**这不改变 G1 的结论**：58 道弃答题中只有 3 题撞上限（其中 2 题判错）。即便这 2 题全部改判为正确，
G 臂弃答错误仍为 6，仍不满足 ≤ 5。

**对生产的影响**：dashboard 的 chat 适配器未设 `max_tokens` 时用 C++ 默认的 4096，比本次评测的 2048 宽松，
但长总结题仍可能撞上。**截断时证据块会原样泄漏给用户**——这是「格式不合则原样返回」策略在截断场景下的副作用。

contradiction_resolution 与 knowledge_update 增益最大——这两类都要求区分「哪条原话是关于所问对象本身的」，
正是证据块强迫模型做的事。

## 4. 这说明了什么

- **先引用后作答作为 grounding 手段是有效的**：在不撞上限的 493 道可答题上 +0.054，且在需要甄别证据的能力上增益明显。
- **作为弃答修复是无效的**：弃答错误 10 → 8。模型摘出「关于 X 本身」的原话时，仍把外围原话判为相关——
  这与诊断（`2026-10-23-abstention-v2-diagnosis.md`）一致：区分「X 的细节从未出现」与「X 的外围事实」，
  在摘录这一步同样困难。
- 按 §1 防线，**不改措辞重跑**。

## 5. 待用户裁定

开发判据只决定「上不上 1M 做弃答验收」，不决定这个改动本身是否保留。两件事分开：

1. **弃答修复**：按规则不上 1M。三个方向（v1 核验、答案出处核验、先引用后作答）都已在同一数据上证伪或无效。
   建议接受弃答代价，不再投入。
2. **先引用后作答作为可答题改进**：+0.042 是**开发数据上的事后发现**，不是预注册的目标，不能直接作为上线依据。
   若要保留，需先修截断问题（例如作答 `max_tokens` 随证据块放宽，或截断时不泄漏证据块），再在**未用过的数据**上
   以可答题收益为主判据重新预注册验证。
