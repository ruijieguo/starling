# Starling 评测组合方案:普通基准不降、强项基准大幅提升

> 撰写日期 2026-07-19。配套文档:同目录 `2026-07-19-starling-locomo-longmemeval-beam-eval-plan.md`(三件套单基准细节)、`docs/superpowers/research/2026-07-19-agent-memory-benchmark-landscape.md`(基准全景与方法论警示)。
>
> 本文回答一个组合级问题:**如何用一套评测,同时可信地证明两件事——(1) Starling 在通用记忆基准上不倒退、力争提升;(2) 在契合其社会心智/矛盾更新能力的基准上大幅提升。**

---

## 0. 一句话主张与判据

- **防守主张(Parity)**:在以扁平事实检索为主体的通用基准上,Starling 作为叠加在既有向量栈之上的认知中间件,**不低于**同后端的朴素 RAG 基线(容差内),且力争总分持平或微升。
- **进攻主张(Lift)**:在要求归属、信息可及性追踪、带来源矛盾修正、视角化弃答的基准/子集上,Starling **相对最强受控基线**取得**大幅、配对显著、且经归因阶梯坐实**的提升。

**两段主张共享一条铁律**:任何"提升/不降"的数字,只有在**同 backbone、同 embedder、同 answer-prompt、同 judge、多种子多轮、报告标准差、且提升幅度超过 judge 对抗审计测得的不可解读带**时才成立。否则一律标注"不可解读",不计入结论。

---

## 1. 组合的三层结构(总览)

| 层 | 目的 | 基准/子集 | 成功判据 |
|---|---|---|---|
| **A 达标层(防守)** | 证明不倒退 | LoCoMo 全量、LongMemEval-S、BEAM 100K/500K | Starling ≥ 朴素RAG − 容差(逐子集);版本间无回归 |
| **B 强项层(进攻)** | 证明大幅提升 | 见 §4,按证据置信度分三档 | Δ vs 最强受控基线 ≥ max(10pp, 2σ),配对 p<0.01,过归因阶梯,超 judge 不可解读带 |
| **诚信脊柱(贯穿)** | 让 A/B 的数字可信 | 归因阶梯 + judge对抗审计 + 标注核查 + 写入成本 + 路由门控 | 每个结论都附其归因证据与不可解读带 |

**报告产物是一张 profile 记分卡,不是单一总分**(§7)。调研反复证明:聚合总分会同时隐藏"刷分假象"和"真实强项",对 Starling 这种能力高度非均匀的系统尤其失真。

---

## 2. 归因阶梯(整套方案的支点)

要同时支撑"不降"和"大升",必须先能回答"这个数字是谁的功劳"。方法沿用技术报告已验证的**同模型在环(same-model-in-the-loop)**范式:同一个 LLM 既抽取、又答题,Starling 只在中间注入结构化记忆——于是任何 Δ 都直接度量*记忆结构对该模型的边际贡献*,而非换了个更强的求解器。

在每个基准上跑一条固定的阶梯,**除"记忆层"这一个变量外全部锁死**(backbone / embedder / answer-prompt / judge / 种子集合 / 语料 hash 全部相同):

| 台阶 | 记忆层 | 作用 |
|---|---|---|
| **S0** | 无记忆(只给问题) | 地板:模型闭卷能答多少 |
| **S_rand** | 随机片段 | 检索是否真的有用(排除"给点上下文就涨") |
| **S_full** | 全上下文(语料塞进窗口) | 长上下文上限;判定"记忆是否被窗口淹没" |
| **S_rag** | 朴素向量 RAG(同 embedder) | **防守主张的对照物** |
| **S_star** | Starling 视角化检索(真实 Extractor 抽取) | 被测系统(端到端) |
| **S_oracle** | Starling 视角化检索(**喂入金标准 statement,绕开 Extractor**) | 抽取上限;分离"表征贡献"与"抽取失真" |

- **防守判据**落在 `S_star ≥ S_rag − tol`(逐子集),理想 `S_star ≥ S_rag`。因为 Starling 不删除检索、只叠加认知层,结构上"不该更差";若更差,说明视角遮蔽或重构误伤了扁平题,是真回归信号。
- **进攻判据**落在 `S_star − max(S_full, S_rag)`:提升必须**超过**长上下文和朴素RAG两个上限,才排除"其实是窗口够大/检索够用"的解释(直接对应 MemDelta 揭示的"换 embedder 就反转结论"陷阱)。
- **归因坐实**:提升必须在**多个 backbone**上同号(如技术报告里 zing-14b 与 deepseek 深阶同为正);只在单一模型上出现的提升记为"待复现"。

> 这条阶梯是把调研中 MemDelta、Benchmark Theatre、Letta"文件系统+grep"三条警示一次性落地的装置。没有它,"大幅提升"这句话不可信;有了它,"不降"也才有对照物。

### 2.1 S_oracle 台阶:把抽取失真与表征贡献分开(防静默失效)

整条阶梯有一个致命的隐患:`S_star` 是**端到端**的——原始对话先经真实 Extractor 抽成带归属的 statement,再进视角化检索。若某基准的文风让抽取崩了(技术报告 §5.3 已实测:文学体/中文/重构叙事上抽取退化,净效应 −9~−20pp),`S_star` 会难看,但你**无法区分**这是"表征没用"还是"抽取没跟上"——而且是**静默失效**:数字照常产出,归因却是错的。SocialMemBench 这类多方对话抽取难度更高,风险更大。

`S_oracle` 是这个隐患的解药:它与 `S_star` 唯一的差异是**抽取来源**——`S_oracle` 直接喂入金标准 statement(人工/规则从基准的结构化标注转写,绕开 LLM 抽取),`S_star` 走真实 Extractor。于是两个差值各自有了干净的含义:

- **`S_oracle − S_rag`** = **表征层的纯贡献**(抽取完美时,视角遮蔽 + 心智摘要 + 弃答到底值多少)。这是进攻主张的**理论上限**,回答"这套表征本身有没有用"。
- **`S_star − S_oracle`** = **抽取税**(真实抽取相对完美抽取丢了多少)。这个差回答"抽取是不是当前瓶颈"。

判据据此细化:
- 若 `S_oracle − S_rag` 显著为正、但 `S_star − S_rag` 不显著 → 结论是"**表征有效,但被抽取拖累**"(诚实主张:机制成立,工程待补),而非"表征无效"。这正是技术报告 §8"强依赖抽取质量"边界的可度量化。
- 若 `S_oracle − S_rag` 本身就不显著 → 表征在这个基准上确实没有结构优势,不该硬吹。
- **金标准来源必须可复现**:oracle statement 的转写规则(从基准标注 → 九元组陈述)固定、hash 进 corpus_hash;不得为刷分手工优化个别条目(否则退化成 MemPalace 式"对着答案打补丁")。

工程上,`S_oracle` 复用 `S_star` 的同一检索路径(§实现规格 PR-0 的 planner 绑定),只把 ingest 阶段从"Extractor 抽取"换成"金标准转写器直接 seed statement",其余台阶锁死变量不变。达标层的扁平题可跳过 oracle(抽取对单跳事实几乎无损),**oracle 台阶主要施加于进攻层**——尤其 SocialMemBench / STALE / HiToM 这些依赖高质量归属抽取的强项基准。

---

## 3. A 达标层:证明不倒退(防守)

**基准**:LoCoMo 全量(~1,540 题四类子集)、LongMemEval-S(~115K tokens,500 题五能力)、BEAM 100K/500K 两档(10M 档列为后续,需真实长语料工程)。

**现状差距**:仓库现有 `scripts/eval_longmemeval.py` 只是小样本 + fixture-mode(90% 确定性 mock)+ 0.55 过门槛;real-mode 已写但 gated 未行使。达标层要把它升级为全量 real-mode 接 Starling 检索管线(`SqliteAdapter + OpenAIEmbeddingAdapter + EmbeddingWorker + SemanticRetriever`,real-mode 骨架已在)。

**指标与阈值**:
- 主指标:逐子集 accuracy(LLM-judge),多种子 ≥5、报告中位数 ± σ。
- **达标带取代过门槛**:不再用 0.55,而用"对齐已发表数字 ± 一个测得的噪声带"作为绿区(LongMemEval 原论文 oracle≈92% / 交互≈58% 的落差本身是参照系)。
- **非回归**:复用 `eval_quality_baseline.py` 编排器的 `corpus_hash` 可比性 + per-metric 容差(默认 0.05,小 N 子集放宽,如 nesting_depth 已有 0.15 先例)。版本 N+1 相对 N,任一子集跌破容差 = REGRESSION,阻断。

**防守层的正确定位**:这里**不追聚合 SOTA**。目标是"逐子集 ≥ S_rag,总分不掉出主流带"。把差异化留给 B 层——这正好规避调研里所有"刷三件套总分"翻车的坑。

---

## 4. B 强项层:证明大幅提升(进攻)

按证据置信度分三档,资源优先投前两档。每个基准都跑 §2 的完整阶梯。

### 4.1 第一档:已证明(直接扩样复现)

- **HiToM(0–4 阶假信念)**:技术报告已实测三阶 +10.8pp、四阶 +8.3pp(deepseek 更高)。动作:扩大样本量、补齐多 backbone 配对、把逐阶 Δ 作为组合的"锚定证据"。这是唯一已落地的大幅提升,报告里应作为"机制确实有效"的存在性证明。

### 4.2 第二档:结构强契合、落差最大、最该赌(机会区)

这些基准里主流无主体系统被调研证明很弱,而 Starling 的核心机制直接对口。预期这是"大幅提升"的主要来源。

| 基准 | 测什么 | 对口的 Starling 机制 | 行业现状(落差) |
|---|---|---|---|
| **STALE** | 隐式冲突 / 记忆失效检测 | 取代链 + 身份字段禁改 + 观测优先 + 级联失效 | 最好模型仅 55.2% |
| **SocialMemBench** | 多方群组记忆 | per-cognizer 归属 + 先遮蔽后排序 | Mem0/LangMem/Graphiti/Cognee 全聚在 0.12–0.18(全上下文 0.369) |
| **MemSyco-Bench** | 记忆诱导谄媚(历史压过当前证据) | 视角遮蔽 + 证据出处标注 + 认识论诚实弃答 | 主流系统普遍脆弱 |
| **BeliefShift** | 理性修正 vs 谄媚漂移 | 有向信任 + 证据锚定 + 置信变更历史 | 7 模型家族 42% 跨会话矛盾未解决 |
| **FanToM** | 对话中"谁知道什么"压力测试 | §3.3(b) 感知可及性追踪(harness 已在) | 模型深阶脆弱 |
| **Faux pas 识别** | 失礼=说话人不知情 | 假信念链(tomeval_server_fauxpas 已在) | — |
| **LongMemEval `knowledge-update` 子集** | 知识更新 | 不覆盖再巩固 + 显式冲突共存 | 各系统弱项 |
| **LongMemEval `abstention` 子集 / BEAM `contradiction-resolution`** | 拒答 / 矛盾消解 | 结构化"我不知道,因为…" + 冲突关系 | BEAM 论文:所有模型都挣扎 |

**为什么这些能大升而三件套总分不能**:三件套总分主体是单跳事实检索,Starling 无结构优势;而上表每一项的题目都**强制要求归属或信息流追踪**,这是无主体向量库结构上无法表达、只能运行时脆弱重建的东西——正是技术报告 §6 那个"Bob 知道吗"实例的能力。

### 4.3 第三档:条件性契合(成熟度依赖,列为探索)

- **PersonaMem / PrefEval**:偏好作为带置信历史的陈述 + 不覆盖 → 擅长"偏好为何改变"的回顾题;但"泛化到新场景"依赖答题模型,增益会稀释。
- **GateMem**:知识边界遮蔽 ≈ 按认识论可及性做访问控制,概念对口但未做安全向评测。
- **记忆投毒鲁棒性(MPBench/MemSecBench)**:观测优先 + 来源冻结 + 不覆盖理论上抗投毒,完全未验证,作为方向性探索。

---

## 5. 诚信脊柱(A/B 两层共用)

直接把调研的方法论警示做成必跑的守门项。缺任何一项,对应结论降级为"探索性"。

1. **Judge 对抗审计(Penfield Labs 法)**:为每题生成"故意错但话题相邻"的答案,用同款 judge 打分,测接受率。**接受率即不可解读带**——所有小于该带的 Δ 一律标注"不可解读",无论正负。这条同时保护防守(避免把噪声当回归)和进攻(避免把噪声当提升)。
2. **标注核查**:抽样核对 ground truth(LoCoMo 已知 6.4% 错误率),报告本地错误率与理论分数上限。
3. **写入成本必报**:检索延迟之外,强制报告 ingestion 延迟 + token 成本(RealMem/MemDelta 证明写入成本才是瓶颈,且高写入成本未必换来准确率)。Starling 的快写慢洗/重放是后台成本,尤其要如实计入。
4. **多种子 + σ + 配对检验**:禁止单次点估计;进攻主张需配对 p<0.01。
5. **语义路由门控**:分布外叙事(文学体/中文/重构)上抽取退化会 −9 至 −20pp;门控把最坏退化收敛到近中性(技术报告实测 −0.7pp)。**门控开/关两版都报**,证明"有益或至少无害"。

---

|---|---|---|---|---|
| P1 | 扁平事实不倒退 | LoCoMo single-hop、LongMemEval single-session | S_rag | S_star ≥ S_rag − tol |

## 7. 记分卡:如何汇报(profile 而非单分)

产出一张固定格式的 profile,让"两段主张"一眼可判、且不可被单一数字掩盖:

```
STARLING EVAL SCORECARD  (backbone=X, embedder=Y, seeds=5, judge=Z)
─ 达标层(防守)──────────────────────────
  LoCoMo    total   S_star vs S_rag: +0.8pp  [PARITY ✓]  judge-floor±4.1pp
  LME-S     total   S_star vs S_rag: +1.2pp  [PARITY ✓]
  非回归 vs v(N):  no subset below tolerance  [✓]
─ 强项层(进攻)──────────────────────────
  HiToM 阶3        S_star − base: +10.8pp  p=2e-5  [LIFT ✓ 双模型同号]
  SocialMemBench   S_star − S_rag: +Δ  |  S_oracle − S_star: +δ(抽取损失)
  MemSyco 冲突     S_star − S_full: +Δ     p=..   [LIFT?/待测]
  LME knowledge-update  ...
─ 诚信脊柱──────────────────────────────
  judge 对抗接受率: 41%(不可解读带=±? pp)
  标注抽样错误率: ?%   写入成本: ?ms / ?tok
  路由门控 OOD 最坏退化: 门控关 −14pp → 门控开 −0.7pp
```

规则:任何 Δ 小于不可解读带 → 显示为 `n.s.`;进攻项未过归因阶梯 → 显示为 `待复现`。**绝不发布掩盖子集结构的聚合 SOTA。**

## 8. 复用现有设施 + 分阶段序列

## 9. 风险登记(锚定技术报告的诚实边界)

| 风险 | 来源 | 缓解 |
|---|---|---|

## 10. 成功标准(组合级,可证伪)

本组合**成功**当且仅当同时满足:

1. **防守**:达标层每个子集 `S_star ≥ S_rag − tol`,聚合落在已发表带内,版本间无回归。
2. **进攻**:至少 HiToM(已证)+ 第二档中 ≥2 个基准,取得 `Δ ≥ max(10pp, 2σ)`、配对 `p<0.01`、超不可解读带、且多 backbone 同号的提升。
3. **诚信**:每个已发布结论都附带其归因阶梯位置、不可解读带、写入成本;无任何掩盖子集结构的聚合 SOTA 声明。

三者缺一,则如实降级对应结论,而非放宽判据——这既是科学纪律,也正是这套组合区别于调研中那些翻车项目的地方。
