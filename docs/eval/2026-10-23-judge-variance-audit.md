# 裁判方差审计：contradiction_resolution 的 −0.125 是噪声，不是容量代价

前序：`2026-10-23-beam500k-k-budget-paired.md`。本文是该文档 §2 里唯一一个"负向且区间不含 0"
的项的追查结果。产物：`judged*.jsonl` 四份（`build/dual_brain_20261017/spike/beam_b500/`，gitignored）。

## 结论

**`contradiction_resolution` 的 −0.125 在裁判噪声之内，不能归因于容量放大。**
更要紧的是，这次追查顺带量出了**官方 judge 自身的噪声地板**——它比这份小样本上多数
能力的"效应"还大。以后凡是用这个 judge 做小样本判读，都必须先扣掉这层噪声。

| | 值 |
|---|---|
| 裁判同答案判两次逐题一致率（n=240） | **88.3%** |
| 判分差的 sd（同答案，n=240） | **0.099** |
| 单题最大判分差 | **1.000**（满分翻到 0） |
| `contradiction_resolution` 判分差 sd | **0.163** |
| 该能力观测效应 | **−0.141**（两次判分平均） |
| 效应/噪声 | **−0.86**（噪声比效应大） |
| 置换检验 p（两次平均） | **0.13** |

## 怎么测的

`b3_judge.py` 只用答案 + rubric 调官方裁判，不依赖重跑作答。所以可以把**同一批答案再判一次**，
两次之间唯一变化就是裁判自己的采样。做了三轮：

1. `judged.jsonl`（旧答案，第一次）— 已有
2. `judged_old_rep.jsonl`（旧答案，复判）— 新增
3. `judged_k30.jsonl` / `judged_k30_rep.jsonl`（新答案，判两次）— 第二次新增

每个能力每臂 12 题，两次判分之差的标准差就是噪声地板的直接估计。

## 单题：为什么 `1|contradiction_resolution|0` 不是容量问题

这题的题目是"我以前同步过服务器时间吗"，gold 有两条 turn：

- **turn 330**：提到 `pool.ntp.org`，"我想同步但不知道怎么在 Node.js 里做"
- **turn 398**：说"我从没同步过"

**两臂都完整渲染了这两条 gold**（旧 8 条原文里含 330/398，新 30 条里同样含 330/398）。
检索层没有差别，答案长度也只差 3 个字符：

> 旧：`Based on the recalled memory, you said on 2024-03-02: "I've never synchronized..."` → `So, as of that statement, no — you had not...`
>
> 新：`Based on the recalled memory, you mentioned on 2024-03-02: "I've never synchronized..."` → `So no, as of that statement, you had not...`

两条答案**都没有提到矛盾**（都没说"你既说过没同步过，也说过想同步到 pool.ntp.org"）。
而 rubric0 明确要求 "state: there is contradictory information"。

所以：**旧判分给 rubric0 的 1.0 是错的，新判分的 0.0 是对的。** 旧裁判的理由原文是
"which directly addresses the rubric criterion by acknowledging the contradictory information"——
这句话在答案里找不到对应内容，是裁判自己补的。这不是容量放大造成的，是**旧的那次判分本身判错了**。

同样的模型、同样的上下文，能力上根本没变——它本来就不会主动陈述矛盾。这暴露的是
**`contradiction_resolution` 这项能力的真实水平（约 0.43）一直被裁判的高分掩盖着**。

## 对全部能力的影响：重算噪声地板

用两次判分平均重算 ON 臂均分：

| 能力 | n | 裁判噪声 sd | 效应（两次平均） | 效应/噪声 |
|---|---|---|---|---|
| summarization | 12 | 0.041 | **+0.186** | **+4.5** |
| instruction_following | 12 | 0.118 | **+0.257** | **+2.2** |
| event_ordering | 12 | 0.072 | **+0.106** | **+1.5** |
| preference_following | 12 | 0.000 | +0.139 | 裁判零方差 |
| knowledge_update | 12 | 0.000 | +0.083 | 裁判零方差 |
| information_extraction | 12 | 0.000 | −0.018 | 裁判零方差 |
| temporal_reasoning | 12 | 0.000 | 0.000 | — |
| multi_session_reasoning | 12 | 0.088 | +0.005 | +0.06 |
| abstention | 12 | 0.200 | −0.125 | **−0.63** |
| contradiction_resolution | 12 | 0.163 | −0.141 | **−0.86** |

**两项负向效应都小于各自的噪声。** 而三个正向大效应里，summarization 和 event_ordering
的效应是噪声的 1.5–4.5 倍——**这两个是这份数据里唯一经得起噪声检验的正向结论**，
正好也是机理上最依赖多句原文的两项，互相印证。

`instruction_following` 效应虽大（+2.2 倍噪声），但它的裁判噪声本身是 0.118，
说明这 12 题上有裁判很不稳的题，单看均值不敢当强结论。

`preference_following` / `knowledge_update` / `information_extraction` / `temporal_reasoning`
的裁判两次判分**完全一致（sd=0）**，这些格子的数字可以放心读。

## 修正后的主结论

| | 原文档 | 修正后 |
|---|---|---|
| ON 臂均分 | 0.595 → 0.652（+0.057） | 0.596 → 0.645（**+0.049**） |
| 配对 bootstrap 95% CI | [+0.003, +0.113] | **[−0.003, +0.105]** |
| 剔除 contradiction_resolution + abstention | — | +0.095（n=96） |
| `contradiction_resolution` | −0.125，区间不含 0 | **−0.141，噪声之内（p=0.13）** |
| `abstention` | −0.083 | −0.125，**噪声之内（p 不显著）** |

**主效应 +0.049 的 bootstrap 区间下界跨过 0。** 原文写的"+0.057 [+0.003, +0.113]"用的是
单次判分，运气好落在 0 以上；用两次判分平均后，下界是 −0.003。**所以"总分提升"这个小样本结论
不稳健，应当撤回"区间下界刚过 0"的说法。**

仍然站得住的：
- **渲染率 +19/−0**——这是确定性指标，不经过裁判，不受本文任何影响。
- **summarization / event_ordering 的正向**——效应 1.5–4.5 倍噪声。
- **弃答恶化的方向**——虽然这次点的效应在噪声内，但 100K（8/40 = 20.0%）与 500K（16.7%→ 本次 3/12）
  三次独立观测方向一致，机理也一致，不该因为单次区间跨 0 就推翻。

不再站得住的：
- "总分 +5.7pp 且区间不含 0"——改为"点估计 +0.049，区间跨 0，不能判定为提升"。
- "`contradiction_resolution` 负向异常"——改为"裁判噪声 + 旧判分错误，容量无关"。

## 这份审计的方法学教训

**官方 judge 在小样本上不是一把精准的尺子。** 88.3% 的逐题一致率听起来不错，但落在
rubric 层面（每题 4 条 × 0.25 粒度）就是平均每 8 题里有 1 题的分会动，且**动起来是 0.25 或 0.5**。
12 题一格的比较，噪声 sd 约 0.16–0.20，比大多数真实效应都大。

以后的做法：
1. **每个判据格子至少判两次取平均**，成本只翻一倍裁判调用（答案侧不变）。
2. **报效应时同时报裁判噪声**。没有噪声估计的格子，不要写"区间不含 0"。
3. **单题翻转必须回看 rubric 原文与答案原文**，不要信裁判给的理由——本文就抓到一处裁判自造理由。
4. 确定性指标（渲染率、token 数、context sha）优先于裁判指标。

## 复现

```
cd build/dual_brain_20261017/spike/beam_b500
# 新答案判两次
.venv/bin/python -I b3_judge.py --answers answers_k30.jsonl --out judged_k30.jsonl
.venv/bin/python -I b3_judge.py --answers answers_k30.jsonl --out judged_k30_rep.jsonl
# 旧答案复判
.venv/bin/python -I b3_judge.py --answers answers.jsonl --out judged_old_rep.jsonl
```

`b3_judge.py` 的 `--out` 支持任意路径，`--answers` 亦然；两次判分之间除采样外无任何差异。
