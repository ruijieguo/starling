# 总结类豁免（先引用后作答）评估预注册

**状态：已冻结（2026-10-24）。冻结前，判定规则已提交（`d87ff69`），且没有用它查看过任何题面。** 冻结后不得在看到结果后修改；
修订按 §7 追加。

## 0. 这不是留出验证

BEAM-500K 7–35 与 BEAM-1M 都已用过：开发评估和验收各用掉一个，而且 summarization 的变差正是在这两份数据上发现的。
本次只检验「豁免是否修好了已知的变差、且没有带来别的损失」，**不产生可以外推的效应量**。上线依据是机制
（豁免后，提示与验收通过前的 B 臂逐字节相同）加上本次检验，**不是**一个新的留出数字。

## 1. 为什么不需要新的 LLM 调用

被豁免的题，提示与 B 臂逐字节相同：两者都是有原文行，但不加证据块指令。验收中这一点已经由一致性闸逐题核对过
（`b_prompt_sha`）。因此，被豁免题的 G′ 臂（G 加上豁免）作答与判分**直接复用 B 臂**；未被豁免的题直接复用 G 臂。
作答模型 temperature 0，复用即是同一提示下的同一结果。

**本次 LLM 调用为 0，token 为 0。**

## 2. 规则

`is_summary_request`（`include/starling/memory/memory_ops.hpp`，`d87ff69`）：用户输入转小写后，只要包含
`kSummaryRequestMarkers` 中任一子串（12 个，按产品语义写成），就判为总结请求。

## 3. 数据与臂

- BEAM-1M 700 题（主）与 BEAM-500K 7–35 580 题（辅）：两份都用验收或开发评估时的 B、G 作答与判分。
- G′ = 被豁免的题取 B，其余取 G。

## 4. 度量

- **S1 规则覆盖**：summarization 题中被豁免的比例（召回率），以及非 summarization 题中被误豁免的数量与能力分布。
- **S2 可答题收益**：G′ − B 的配对差（BEAM-1M 630 题），bootstrap 95%（5000 次，种子 20261024），并与验收的
  G − B（+0.022 [+0.001, +0.042]）对比。
- **S3 summarization**：G′ − B（应接近 0）与 G − B（−0.112）对比。
- **S4 误豁免代价**：被误豁免的非总结题上，G′ − G 的差（也就是因为豁免而失去的先引用后作答收益）。
- 辅：BEAM-500K 7–35 上同样的 S1–S4。

## 5. 判据

| 编号 | 条件 |
|---|---|
| **E1** | BEAM-1M summarization 召回率 ≥ 80% |
| **E2** | BEAM-1M 可答题 G′ − B 的 bootstrap 下界 > 0（不弱于验收结论） |
| **E3** | BEAM-1M 非 summarization 题误豁免 ≤ 5%（≤ 31/630） |

- 全过 → 上线豁免：开 PR 合入 main。
- 任何一条不过 → 不上线，结果照实记录，**不改关键词重查**（防线同开发评估 §1）。

## 6. 已知偏差

1. 两份数据都已用过，summarization 变差是在这两份数据上发现的。
2. 关键词表是英文的，BEAM 题面也是英文；中文等其他语言的总结请求不在本次检验范围内。
3. 复用依赖 temperature 0 下同一提示得到同一输出。B 与 G′ 在被豁免题上是同一次调用的同一份输出，不存在采样差异。
