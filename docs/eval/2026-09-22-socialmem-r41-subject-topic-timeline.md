# SocialMemBench R4.1 人物—话题—时间链评测报告

日期：2026-09-22。R4.1 是 R4.0 之后的独立开发诊断，使用相同 57 题、父数据库、模型、裁判和 600 HTTP 预算；R4.0 目录未修改。

## 结论

R4.1 主体优先策略把精确原话锚点覆盖从 R4.0 的 46/104 提升到 **55/104**，但检索臂准确率由 R4.0 的 19/57 降为 **17/57**；原生回答臂为 **19/57**，与 R4.0 持平。相对 R3.5 的 16/57，分别净增 1 和 3，网络 bootstrap 区间均跨零，仍未达到“净增至少 5 且区间下界大于 0”的继续门槛。

这说明主体时间链是必要修复，却不能单独解决 SocialMemBench 的回答能力。部分问题需要第三方观察、他人先前认知或集体背景；R4.1 将这些句子全部排除后，来源覆盖更接近形式上的人物时间链，却损失了答案所需的支持关系。

## 固定实验与结果

| 方案 | 正确 | 准确率 | 技术失败 |
|---|---:|---:|---:|
| R3.5 | 16/57 | 28.07% | 0 |
| R4.0 检索臂 | 19/57 | 33.33% | 0 |
| R4.0 原生回答臂 | 19/57 | 33.33% | 3 截断 |
| R4.1 检索臂 | 17/57 | 29.82% | 0 |
| R4.1 原生回答臂 | 19/57 | 33.33% | 3 截断 |

R4.1 两臂共用一次新检索，实际 544 次 HTTP：345 次查询 embedding、114 次回答、85 次裁判；零重试、零未决账本。原生回答臂的回答及裁判 token 为 190609，检索臂为 107821，成本差异与 R4.0 同方向。

R4.1 相对 R3.5 的 network bootstrap 95% 区间（100000 次、seed 20260921）为：检索臂 +1.75pp，[-6.98, +12.50]；原生回答臂 +5.26pp，[-4.17, +16.67]。两臂相对彼此净增 2 题，区间 [-3.77, +9.30]。这些区间只描述 6 个网络开发集，不包含生成重复方差。

按答案格式，R4.1 检索臂为选择题 9/13、短答 1/8、长答 7/36；原生回答臂为 9/13、1/8、9/36。R4.1 原生回答仍有 Q7 两题和 Q8 一题截断，失败计零，不重试。

## 来源诊断

R4.1 的精确 `(speaker, turn_id)` 原话命中为 55/104；R3.5 为 53/104，R4.0 为 46/104。按题型：Q1 14/17、Q2 1/5、Q3 1/7、Q4 4/9、Q5 3/10、Q6 0/6、Q7 6/13、Q8 26/37。Q8 恢复了 R3.5 的总体原话覆盖，Cass 的变化题和 Preet 的实体关系题都不再被第三方邻句挤出。

代表性修复：

- Cass 的路线选择变化题保留 5 个有效会话中的 Cass 自身来源，实体关系问题不再启用人际互动车道。
- Bev/Marcus 两人关系仍识别为 `human`，保留直接回应和第三方叙述的真实 speaker。

新损失也很明确：

- Raj/Luca、Priya/Nora 等问题同时询问主体行为与另一人的“已经知道/此前了解”；R4.1 只保留目标人物来源，丢失了支持性第三方句。
- 单人物偏好题中过度主体化，删掉了能解释群体背景或他人反馈的来源。

因此 R4.2 保留 R4.1 的主体优先时间链，并加入受限的支持性第三方车道；该车道只在问题含“已知、揭示、说明、为何”等认知或解释线索时占一个来源名额，不能把第三方数量当作主体时间覆盖。

## 工程验证

R4.1 新增 `SourceProfileV3` 三项测试，相关 Source*/EvidenceAnswer/GroundedMemory 测试共 83 项通过；完整 CTest 1247 项通过，沙箱跳过的本地回环测试沿用上一轮移出沙箱后的通过证据。R4.0/R4.1 运行器合同测试 22 项通过。R4.1 冻结目录离线完成 57 次检索和 114 个回答终态，网络请求为零；真实目录通过任务、提示、账本和 completion seal 核验。

R4.1 不晋升生产，生产默认仍为 `semantic_claim_contract=false`、`claim_protocol_retry_budget=0`。详细原始回执、账本和 coverage 统计分别保存在 `build/socialmem_20260922_r41_subject_topic_timeline_real` 与 `build/socialmem_r41_checks_*`。
