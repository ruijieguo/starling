# SocialMemBench R4.2 支持性第三方证据评测报告

日期：2026-09-22。R4.2 是 R4.1 之后的独立开发诊断，使用同一 57 题范围、R3.5 父快照、`qwen3.8-27b` 回答与裁判、零重试和 600 次 HTTP 上限。R4.0、R4.1 的封存目录没有修改。本报告只描述 R4.2 的可复核结果，不把来源覆盖或离线合同通过率当作生产质量。

## 结论

R4.2 在 R4.1 的主体优先时间链上增加了受限支持车道。检索臂正确 **17/57（29.82%）**，原生回答臂正确 **19/57（33.33%）**；相对 R3.5 的 16/57，分别净增 1 和 3 题。两臂配对净增 2 题，网络 bootstrap 95% 区间为 **[-3.64, +9.80] 个百分点**，继续门槛仍未满足，因此不晋升生产。

支持车道解决了一个明确的来源缺口：带有“已经知道、说明、为何、揭示”等认知或解释线索的问题可以保留一条非目标人物的支持性发言，同时保持主体时间链。它没有解决更大的语义缺口：来源集合仍缺少可靠的事件状态链、信念归属和全体成员覆盖，且原生回答在固定 512 token 下发生两次截断，两个裁判请求超时。R4.2 证明“增加一条第三方来源”是必要条件之一，不能单独带来整体准确率提升。

## 来源覆盖与支持车道效果

统计使用公开锚点的精确 `(speaker_display_name, turn_id)` 与 `source_refs` 匹配。锚点命中只证明原话被选入上下文，不证明该原话包含完整答案要点。R3.5 精确命中为 53/104，R4.2 为 52/104；把结构化声明的 `source_turn` 作为出处回指并集后，R3.5 为 60/104，R4.2 为 57/104。

| query type | 锚点数 | R3.5 原话命中 | R4.2 原话命中 |
|---|---:|---:|---:|
| Q1 | 17 | 10 | 14 |
| Q2 | 5 | 3 | 1 |
| Q3 | 7 | 2 | 1 |
| Q4 | 9 | 6 | 4 |
| Q5 | 10 | 3 | 3 |
| Q6 | 6 | 1 | 0 |
| Q7 | 13 | 2 | 6 |
| Q8 | 37 | 26 | 23 |
| **合计** | **104** | **53** | **52** |

R4.2 的诊断字段显示支持车道按设计工作：认知或解释问题最多选择一个第三方来源；纯时间变化题 support limit 为 0；双人物关系题仍使用 human relation 车道。典型的 Priya/Josh 题 `support_requested=true`、`support_selected=1`，Raj/Luca 题也保留了第三方支持；但这些支持句不能替代主体的早期状态、触发事件和后来状态。

来源缺口的可复核例子如下：

- `Q6_n2a7b8c9` 要求判断“所有成员”是否接受 Ngozi 的圣诞食物，诊断明确给出 `no_selected_utterance:Chidi`，两臂均从父快照的正确退步。当前行为车道只保证若干高相关人物，不能保证全体被问成员各有一条证据。
- `Q8_r3b8c9d0` 的 Cass 路线选择变化题命中 3/3 原话，但原生回答仍因 `completion_truncated` 失败。来源已经存在，问题转移到事件状态链的压缩表达和输出预算。
- `Q8_ph9s4c1` 的 Diane 变化题只命中 1/2 原话，缺少“触发—首次显现—后续独立决策”的完整链；原生回答虽然判对，不能据此证明选择策略已稳定解决该类题。
- `Q8_a3b4c616` 的 Priya 摄影变化题从父快照 2/2 降至 1/2，加入支持车道后仍可能挤掉旧状态或触发证据，说明来源名额需要按事件角色分配，而不是只增加第三方名额。

## 能力短板诊断

### 1. 谓词目录变丰富，但事件状态没有形成可回答的链

R4.2 冻结数据库中结构化声明共 102 条：`believes` 56、`prefers` 20、`decided_on` 12、`feels` 6、`uncertain_about` 4、`knows` 3、`owns` 1。当前样本没有 `promises`、`doubts`、`responsible_for`、`requires`、`forbids` 的已保存实例；因此不能把目录中存在这些谓词误称为它们已在 SocialMemBench 上被验证。

现有 claim 记录保留 actor、predicate、modality、polarity、topic、source turn 和时间，但没有显式的“前态—触发—后态”事件链接。回答器看到多个独立声明时，仍需从原话自行重建状态转移；这正是 Cass、Diane、Priya 等 Q8 题在有来源时仍不稳定的原因。

### 2. 他人信念与已知关系的归属仍依赖回答模型推断

`attributed_to` 可以为空或指向来源归属，但当前检索和上下文没有把“谁知道谁的什么状态”作为单独的关系角色展示。R4.2 支持车道只保证一条第三方句，不能保证该句同时包含主体状态、信念持有者和命题对象。Raj/Luca、Priya/Josh 等题因此仍可能把观察者、被描述者和信念持有者混淆。

### 3. 全体成员和反例覆盖没有独立配额

`asks_for_all_members` 只把所有授权 holder 放入关注集合，最终 profile 仍以相关性和行为队列填充。一个成员没有高 BM25 命中时会被遗漏，即使诊断已经能指出缺口。Q6 的退步表明“发现缺口”必须进一步变成一条受限的成员覆盖车道，并保留“未知”而不是用其他人的事实填空。

### 4. 原生回答的输出协议仍有技术损失

R4.2 原生臂 57 次回答中 2 次 `completion_truncated`，另有 2 次裁判 `Timeout was reached`；检索臂无技术失败。原生回答及裁判总 token 为 190223，检索臂为 105312，约高 80.6%，但正确数只多 2 题。继续增加上下文或回答长度没有证据支持，下一轮应先把状态链压成固定的“早期状态 / 触发 / 后期状态 / 归属”短结构，并在 512 token 下做无截断合同测试。

## 工程核验与生产决策

R4.2 C++ 相关回归为 86 项通过，完整 CTest 为 1250 项通过；R4.2 Python 合同为 4 项通过。冻结目录离线重放完成 57 次检索和 114 个回答终态，真实目录的 `verify` 重新通过。统计脚本、账本和 completion seal 之外的诊断输出位于 `build/socialmem_r42_checks/`，未写入封存目录。

这些是开发集和工程证据，不是全量基准成绩。父快照只有 35/36 完整 holder，仍包含 partial scope；R3.5 比较同时包含服务时间和查询 embedding 变化；bootstrap 以网络为单位且不覆盖生成方差；公开锚点也不是完整答案要点。生产默认继续保持 `semantic_claim_contract=false`、`claim_protocol_retry_budget=0`，R4.2 不晋升。

## 下一轮优化方案：R4.3 事件状态与信念归属车道

下一轮仍严格遵循“中文设计 → RED 测试 → C++ 实现 → 离线验证 → 真实评测”。候选方案为新增实验策略 `evidence_profile_v5`，不改写 v2/v3/v4 和任何封存目录：

1. **事件状态车道**：对变化/模式问题，在 C++ 中为主体保留早期状态、明确触发或回应、后期状态三个角色；角色只能由已有 source turn 或结构化 claim 的 source span 支持，缺一项就输出诊断缺口。
2. **信念归属车道**：把 actor、被谈论的人、命题 topic、`attributed_to` 和真实 speaker 分开呈现；“谁已经知道谁的什么”至少需要主体发言和归属支持句各一条，不能把第三方数量当作归属完成。
3. **成员覆盖车道**：对“每个人/所有成员/是否都”问题，每个 focused holder 最多占一条来源名额；没有命中时记录 `member_missing`，答案提示必须明确该成员证据不足。
4. **短回答包**：在 C++ `grounded_memory_answer_prompt` 中引入固定短结构提示，优先输出问题要求的角色和状态，减少重复引用；先用 RED/GREEN 验证 512 token 下不截断，再与 R4.2 同协议配对。
5. **谓词验证边界**：继续使用 C++ `PredicateCatalog`；先统计新增谓词在真实抽取中的空候选和拒绝原因，再决定是否扩展 `promises/doubts/responsible_for/requires/forbids` 的抽取示例。目录存在不等于基准能力已验证。

只有当 R4.3 相对 R3.5 共同正常题净增至少 5、网络 bootstrap 区间下界大于 0、技术失败不增加且来源角色诊断没有回归时，才重新讨论生产晋升；否则保留实验结果并继续分层诊断。
