**改动归因：所有跨轮判分变化都出现在 prompt 没有变化的题目。** 检索臂变更 prompt 的 6 题仍是 2/6；原生回答臂变更 prompt 的 8 题仍是 3/8；这些题没有任何正确/错误互换。原生臂其余 49 个相同 prompt 从 15/49 变为 12/49。结果与跨运行的生成/裁判波动一致，不能把检索臂 +1 宣称为代码收益，也不能将原生臂 -3 全部归因于选路改动。此次单次运行不能进一步分离生成与裁判方差。

## 检索阶段诊断

真实检索 57/57 技术成功，metadata 加载/回连尝试/回连成功均累计 1142，拒绝 0。这是逐题累积量；底层 7 scope 中按 scope 计数实际有 102 条 claim 存储记录，分布在 90 个来源话轮，不能解释成 1142 条独立知识。423 条可见来源中约 21.3% 有这些 claim；这只是元数据覆盖比例，不是抽取召回率，因为未建立逐话轮人工金标。

状态链实际新选入 38 条 claim，成员车道 20 条 claim，成员普通来源成功回退 7 次；归属车道为 0。57 题的车道计数与最终渲染完全一致，整行 UTF-8 字节预算核验通过。

26 题触发信念归属，底层 102 条 claim 全部为第一人称且 attributed_to 为空；现有归属资格排除了 actor=speaker 且无 attributed_to 的自述。因此“我知道/相信某事”这一合法来源不能进入归属车道。这是明确的车道资格能力缺口，不是网络或回连故障。

另外 11 个来源话轮各关联多个 claim，而 `load_claim_views` 仍为每个来源只保存一个 `ClaimView`，后读到的声明覆盖先前声明。102 次有效加载最终只有 90 个来源视图；遇到同一话轮同时表达偏好、知识和决策时，车道可能丢掉所需语义。这里是静态代码和真实库基数支持的候选缺陷，尚未用插入顺序交换的 RED 回归验证；不能声称已修复。

相对 R4.5，来源集合只改变 6/57 题；来源锚点总命中保持 48/104：Q3 从 2/7 降为 1/7，Q8 从 19/37 升为 20/37。Q6 仍为 0/6。57 题的 statement 集合均相同；检索臂 51/57 的 prompt 完全相同，原生回答臂 49/57 完全相同。因此跨轮 QA 差值需要按 prompt 是否改变分层，不能把同 prompt 的生成/裁判波动都归因于选路优化。

## 下一轮优先级

1. **P0：完善信念承载者与来源说话者的原生规则。** 第一人称知识/信念和第三方转述是两条合法路径；仅在实际 holder、actor、speaker、attributed_to 和证据验证一致时准入。问题没有点名时不凭空解析代词或制造人物关系。先为自述知识、正确转述、错误承载者和字段缺失分别写 RED。
2. **P0：来源到多 claim 的原生视图。** 保留同一 source 的全部有效 claim；任一合格 claim 可满足相应车道，来源只占一个上下文名额。无效 sibling 不应覆盖有效 sibling；交换入库顺序后选路应不变。先文档，再写上述 RED，再实现 C++。
3. **P1：人物、话题与时序联合检索。** 当前时间端点优先可能选择早晚但无关的陈述。增加 topic 可解释匹配及无证据缺口，保留整句上下文和因果不确定性；优先研究 Q6 无锚点、Q8 状态变化失败题。
4. **评测：** 先复用相同冻结库隔离检索变化；另行扩大抽取覆盖实验才重新写库。分别报告输入相同/改变题、技术可用率、锚点覆盖和 QA。57 题用于开发诊断，通过后再用未参与优化的数据检验；避免把同一小样本的反复调参成绩当全量提升。
