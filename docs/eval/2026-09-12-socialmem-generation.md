## 主题与时间：字段完整性和标签限制

本轮 synthetic 共存 14 条补充声明，14 条均有非空 topic，12 个评价样本内的 12 条也全部有非空 topic。严格主题仍只有 1/14，已不能解释为“模型不填主题”：11 个对象已覆盖的目标，其 topic 与冻结标签字面不符。例如实际 `the certification exam` 对标签 `certification exam`、实际 `the fellowship` 对标签 `fellowship`，以及实际原因短句对标签较短主题。这些字段已通过原生同源与对象保留校验；字段存在率不等于主题语义正确率。

`possible_not_decided` 正确保留来源中的 `yet`，但冻结标签的 `time_text` 为 `""`，所以该目标时间字段不得分。正式分数和标签不回填；[分析 JSON](2026-09-12-socialmem-generation-analysis.json)单列 11 条字面不匹配诊断及唯一时间差异。

`decision_change` 的两个独立目标均未覆盖。来源是 `Last week … Today …`，模型返回 `last week` 和 `today`，大小写变化触发现有逐字时间校验，两个候选均被拒。这是可复现的生成契约遵从问题；本轮没有放宽校验或转换来源大小写。

4 个无补充目标样本仍明确排除，不能用正目标覆盖率估计补充通道的整体准确率。其中 `preference_contrast` 被准入为 `feels / NEG / does not prefer the green room`，`preference_qualifiers` 被准入为 `feels / prefer a shorter meeting`，暴露偏好与情绪关系混淆；前者还同时包含关系否定与对象否定。两例均需单独语义复核，即使基础记忆使整个候选集合获得多数 YES，也不证明新增行正确。评价样本内未匹配联合目标的 11 条预测只作诊断计数，不等于 11 个假阳性。

## 结论与后续优化顺序

本轮已证明生成指导能与现有 C++ 契约兼容，并在这次固定诊断中提高对象覆盖和 synthetic 多数通过数。重复键、非法准入原因、时间词原样保留、偏好/情绪边界及跨时段对比仍是主要瓶颈，生产准入没有成立，未运行 1,031 题全量。

1. 先解决输出协议可靠性：明确每个字段只出现一次，原文大小写也属于时间限定；以本轮原始失败响应和独立中英文反例设计 RED 用例。完整 JSON Schema/服务能力协商需要单独验证，继续保留原文与失败，不进行 Python 清洗或静默补写。
2. 再验证谓词边界：覆盖偏好与情绪、关系否定与对象否定、转述正例及跨话轮错引。核心判断继续由 C++ 唯一实现，先检查误收和误拒，再看通过率。
3. 另行版本化扩展标签，把逐字字段覆盖、来源跨度合法性、人工主题语义和无补充目标误收分开；新标签在下一轮前冻结，同时保留现有标签和分数，不能用本轮输出来改写当前成绩。
4. 目标人物能稳定入库后，再评价时间/主题检索与 Q9 早晚状态覆盖。下一轮继续固定对照、P1 兼容、逐例不退步和 Q1/Q9 证据复核，不把本轮 13/16 作为扩大或默认启用的依据。

后续条目为本轮结果导出的工作顺序，未在本轮追加实现或改变评分协议。总设计、两份技术报告、12 个子系统及相关专项已同步本轮状态；其余设计职责登记在 [中文设计同步清单](../design/claim_contract_sync.md)，历史快照与各轮原始归档保持。
