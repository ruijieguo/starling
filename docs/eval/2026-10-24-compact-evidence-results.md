# 压缩证据块评估结果

预注册：`2026-10-24-compact-evidence-prereg.md`（冻结于 `4d2e644`；修订 1 于 `b104767`，在 C 臂作答之前提交）。
数据：BEAM-1M 全量 700 题。C 臂新跑 629 题；总结豁免的题复用 B 臂结果。

## 1. 结论

**按冻结判据，K1 不过 → 不替换，保留原版指令。** 按预注册规定，不改措辞重跑。

| | G（原版） | C（压缩版） | 判据 |
|---|---|---|---|
| **K1 非总结可答题质量（560）** | | C − G = **−0.016 [−0.038, +0.006]** | 下界 ≥ −0.025 ✗ |
| K2 completion 中位数 | 457 | **265**（0.58 × G） | ≤ 0.6 × G ✓ |
| K3 弃答错误（70） | 15 | 15 | ≤ G + 3 ✓ |
| K4 无回复轮 | | 0/700 | ≤ 2% ✓ |

运行健康：700/700 完成，一致性闸 0 失败，无传输失败，缺判 0。token 用量 9.2e6（作答 4.7e6 + 判分 4.5e6），
在批准的 1.2e7 以内。

**这次是同时没达到两个目标，不只是检验力不够**：点估计 −0.016，比先引用后作答的全部收益（+0.022）的七成还多。
区间上界 +0.006，说明数据不支持「压缩没有损失」这个结论。

## 2. 损失落在哪里（描述性）

| 能力 | C − G |
|---|---|
| contradiction_resolution | **−0.081** |
| event_ordering | −0.033 |
| temporal_reasoning | −0.030 |
| preference_following | −0.025 |
| instruction_following | −0.013 |
| information_extraction | +0.001 |
| multi_session_reasoning | +0.025 |
| knowledge_update | +0.025 |

**contradiction_resolution 损失最大**，而它正是先引用后作答增益最大的能力（两个数据集上分别为 +0.18 和 +0.14）。
压缩后证据条数几乎没变（中位 5 → 4），但每条的字数砍掉一半多（798 → 378 字符）。
合理的解释是：判断两条记录是否矛盾，需要看到原话的细节（限定条件、时间、数量）。只保留 15 个词，就丢掉了这些细节。
先引用后作答之所以有效，**价值恰恰在于把原话完整摆出来**。

## 3. 这次评估花得值不值

值。这次确认了先引用后作答的收益主要来自原话的完整呈现，而不是「列出相关条目」这个动作本身。
所以继续压缩的方向，应该是**减少条数**（只列真正相关的），而不是**压短每一条**。不过开发集上中位只有 6 行，可压缩的空间有限。

延迟问题仍然存在：completion 中位 457，B 是 107。这次压缩确实把它降到了 265，但代价是质量。

## 4. 后续

- 保留原版指令。分支 `feat/compact-evidence` 不合入；评估文档单独合入。
- 延迟没有现成的零代价解法：证据块必须先于回答生成，才能约束回答，所以无法并行。剩下的选择是接受延迟，
  或者在界面上显示「正在核对记忆」之类的提示，让等待可以被感知。后者属于产品层面的决定，不在本次评估范围内。
