## 问题证据与范围

## 方案与取舍

采用原生提示约束与窄范围关系检查：生成端明确键唯一、时间大小写原样复制、主题与时间必须来自同一所引话轮；准入端提供可执行的合法原因目录，说明极性/时间不符应选择已有原因。解析器继续严格拒绝重复键和未知原因，不能自动修复响应。

仅追加提示不能保证偏好误收消失，因此对 `feels` 候选对象中的明确偏好谓词前缀增加 C++ 确定性拒绝。完整 JSON Schema 服务能力协商需要独立验证；扩大中文情绪词白名单或用整话轮偏好关键词判定容易误拒，均不纳入本轮。

## C++ 行为契约

1. 输出协议要求每个对象内每个键只出现一次，包括 `event_time`；参考示例由原生 JSON 编码生成。时间词直接从所引来源复制，保留大小写及 Unicode 字节，不能从另一话轮借用 `yet`。现有逐字时间与主题规则不放宽。
2. 准入原因使用 C++ 唯一目录：`supported`、`wrong_relation`、`not_asserted`、`wrong_attribution`、`wrong_scope`、`missing_context`、`missing_time`、`unsupported`。提示独立输出 `ADMISSION_RULES_JSON`，验证器复用同一目录校验枚举；`retain=true` 仍当且仅当原因是 `supported`。极性或范围不符用 `wrong_scope`，时间缺失/不符用 `missing_time`；不把模型输出的未知原因自动映射成合法原因。
3. `feels` 的对象若以明确偏好谓词开头，返回 `scope_failure` 语义拒绝。英语覆盖 `prefer/prefers/preferred/preferring`，可带人称代词及 `do/does/did/would`、`not`；中文只覆盖明确的 `偏好/更偏好/不偏好/更倾向于` 等偏好谓词前缀。实际 actor 前缀后出现同类谓词也拒绝；不以来源中出现偏好词触发拒绝。`喜欢` 单独可能是情感，不作中文一刀切规则。
4. `sad about preferring ...`、`对偏好变化感到焦虑` 等情绪为主的对象保持送往模型准入；混合来源中其他偏好句不能屏蔽合法情绪。该窄检查不宣称覆盖完整自然语言语义。直接 Bus 写入与持久化回读复用现有原生契约，历史原始库不改写。
5. 通用示例继续与实际来源隔离，不引用冻结评测人物或主题；首个时间示例改为句首大写时间，验证原样可接纳、改小写仍拒绝。准入原因目录和示例是提示的一部分，不作为当前源证据。

## 复审边界补充（实现前再次补 RED）

复审复现 `have/has preferred`、`I'd prefer`、`倾向于/不倾向于` 等明确偏好形态漏拒；另复现 `preferred seat being taken makes me sad` 和 `偏好被否定让我很难过` 被简单前缀误拒。扩大有限的助动词/缩略词与中文偏好形态，同时对带有情绪谓语、使役/因果结构或并列分句的复合对象保守地交给原模型准入。此处识别的是句法提示，不建立情绪词白名单，也不保证没有句法提示的自由改写均被正确分类。`prefer X but feel Y` 等完整复合句不由前缀规则拒绝。原有明确认知命题校验继续执行。先添加真情绪、复合句和新增偏好形态测试，确认失败后实现。

补充被动感受边界：`preferred`、`preferred by my team`、`preferred over other options` 可以描述被偏爱的感受，不自动视为主体的主动偏好；保持准入进一步检查。

句尾标点不能改变关系判断：纯偏好加标点仍拒绝，裸 `preferred` 的被动感受加中英文句尾标点仍送往准入；两类方向均有回归用例。
