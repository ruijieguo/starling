# SocialMemBench R4.9 主题相关性与成员证据排序设计

日期：2026-09-24。状态：已按文档 → RED → C++ 实现 → 回归 → 离线 → 真实复评完成。以下保留事前设计与停止条件；实际结论见[评测报告](../../eval/2026-09-24-socialmem-r49-topic-ranking.md)。R4.9 检索 17/57、原生回答 16/57，较 R4.8 各净减 1 题；来源锚点 48→51/104，未证明准确率提升，不晋升。

## 1. 已知问题和假设

R4.8 的 Q6 六个公开锚点全部存在于授权候选池，却全部未渲染，也没有字节预算拒绝。现有 v6 在人物匹配之后以未加权的词重合数排序，常见问句词与实质主题词贡献相同；随后成员车道 `stable_partition` 将任意有 claim 的来源提升到无 claim 的来源之前。合同有效性不保证当前问题的相关性。

这两处机制是待由独立反例和消融验证的假设，不预设能够恢复六个锚点。公开锚点、金标和题号只能用于事后诊断，不参与选择逻辑、参数或词表构造。

## 2. C++ 设计

1. 提取当前原生 BM25 计算为一个内部函数；原始完整 query 的相关性使用原公式、相同排序与参数（k1=1.2，b=0.75）。共享算法避免在不同入口或 binding 复制核心逻辑。
2. v6 额外计算 `topic_score`：从问题去掉关注人物姓名 token，以及固定的英文功能词/疑问词，保留否定词、实质名词和其他语言 token；使用相同授权来源池的 BM25 统计，不引入外部语料或新模型。词表固定在实现前，不按基准题目增删；中文分词和词干还原不属于本轮。
3. v6 全局和会话候选在人物匹配后先比较 topic_score，再沿用既有关系/完整相关性与时间顺序。v2-v5 继续使用原 topic_overlap；topic_overlap 保留为诊断字段。
4. v6 成员队列先按 topic_score、完整 query score 排序，仅两者相等时才优先有有效 claim 的来源，最后按时间和稳定来源身份排序。不得用另一人的发言替代成员自述；状态和归属车道的合同资格不改。
5. 增加诊断 `topic_relevance`（来源 trace）和 `topic_terms`（profile），仅解释排序，不注入新证据、不解释为语义正确率。空主题查询的主题分数为零，回到完整相关性、claim 同分和稳定时间顺序。

函数词范围固定为：a/an/the；疑问词 what/which/who/whom/whose/why/how/when/where；助动词/系词 do/does/did/is/are/was/were/be/been/being/has/have/had/can/could/would/should/will/may/might；常见代词及连接介词 and/or/of/to/in/on/at/for/from/with/by/as/that/this/these/those/it/its/they/their/them/he/his/him/she/her/we/our/us/you/your/i/my/me/s。不移除 not/no/never，不加入摄影、饮食、徒步等基准领域词。

## 3. 方案与取舍

保留原 BM25 直接排序实现最小，但姓名、问句功能词仍影响主题。引入 LLM 重排可能解决同义表达，却同时增加成本与评测变量。本轮选择复用原生 BM25 的主题分数，先纠正可复现的词重合/metadata 优先偏差。词汇方法不能解决无同词的语义关联，也不能保证多事件阶段链完整，相关能力另轮验证。

## 4. 测试先行与离线消融

先用与基准无关的人名和领域写原生测试：

- 多个问句常用词不能压过同一人物的直接主题来源；问句中姓名重复不增加主题得分。
- 稀有主题词优于只匹配大量常见词的异主题来源；全局名额和单会话选择采用同一主题信号。
- 无 claim 的直接原文优于有 claim 的异主题来源；相同相关性时有效 claim 仍可决胜。
- 名称-only/空主题查询确定性、来源隔离、UTF-8 整行预算和最终计数一致；v5 兼容回归。

固定两个预注册实现步骤，不根据金标挑选候选：A 只加入主题相关性，保持成员 claim 优先；B 在 A 上纠正成员 claim 优先规则。每个步骤对应先 RED、后 C++ 实现与定向 GREEN。A 只作零网络机制消融，最终候选预先固定为 B，必须通过全部测试。分别用独立冻结目录与相同替身 embedding 跑 57 题，与 R4.8 离线对比实际 source、block、prompt、计数和公开锚点。记录得失，不只报告改善题。

## 5. 真实评测与停止条件

完整 CTest、相关 Python、HTTP 边界及离线封存通过后，若 B 改变实际上下文且无证据合同/预算/隔离回归，执行独立真实双臂评测。模型 qwen3.8-27b、embedding qwen3.7-text-embedding、57 题/7 scopes/6 networks、k10、至少7 sources、8000 bytes、answer512、judge64、4 workers、零重试，整轮最多600 HTTP，原评分保持。

不将锚点变好当作 QA 晋升。相对 R4.8 分层比较同 prompt/变更 prompt 的正确率、相同答案裁判翻转；相对 R3.5 的事前门槛仍为净增至少5且 network bootstrap 区间下界大于0，父库完整性和保留集限制仍保留。若上下文无变化则不重复生成；若有变化但 QA 无收益，则封存失败结果并定位语义/事件链短板，不调整词表追分。

## 6. 实际验收与设计边界

A 的 4 项新增测试得到 3 个预期失败、1 个控制通过，随后 65/65 定向通过；B 的 4 项新增测试得到 2 个预期失败、2 个控制通过，最终 69/69 通过。CTest 1268 通过、23 沙箱跳过、0 失败；HTTP 补跑 30/30、Python 65/65。离线 A/B 分别完成独立冻结消融，最终候选仍为事前固定的 B；真实 114/114 正常、547/600 HTTP、零重试，五个实验封存核验通过。

相对 R4.8，真实 41/57 题 source/block 改变、statement 全不变。改变 prompt 子集检索净 0、原生净 −1；另发现 1 条完全相同答案和裁判输入的判分翻转。Q6 两臂均从 1/3 提升到 2/3，但来源锚点仍为 0/6，六个关键原文主题分数均为零。词汇排序不能建立跨表达的语义联系，也不能保证使用同一次对话的响应或事件阶段；后续按独立设计验证原生语义证据连接和事件约束，不以本轮局部收益修改晋升条件。
