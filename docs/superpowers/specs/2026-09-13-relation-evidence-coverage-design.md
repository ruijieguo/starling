## 本轮关系修复

**实施细化（2026-09-13）**：协议阶段已冻结源码并通过新旧模式离线归档核验。真实服务请求被自动审批拦截，故本阶段先做本地验证，不改变输出模式或提供商。关系修复采用 C++ 共享关系说明及 `relation_boundaries` 目录，同时进入抽取和准入提示；不增加按转交关键词或情绪词表拒绝的确定性规则。新增独立中英来源用例验证提示契约、原生解析、准入决策与 Bus 持久化；Fake 只能证明这些工程路径，不证明模型已理解新边界。

### 未决定单个行动

设计前 `uncertain_about` 提示中的“explicit unresolved alternatives/choice”被模型误解成必须列出多个选项。`possible_not_decided` 原文的“尚未决定是否接受实习”具有明确未决对象，现有关系足以表达；本轮共享目录已澄清单行动选择的边界。

C++ 唯一关系目录将其定义为“明确未解决的选择，包括是否做单个行动”；`uncertain_about/BELIEVES/POS` 保留未决定限定和原主题。不能因为只提到一个行动就拒绝；也不能把任何“可能做 X”自动推断为存在未决选择。仅表达不知某个世界事实、提出问题、愿望或被动建议，不因此准入。与冻结题目无关的中英文正反例先 RED，示例不使用题目人物或主题。

### 操作性路由与明确决定

P1 新增的 4 条 `decided_on` 都是转交登录问题、询问负责同事或同步线索，来自 eval-032、eval-034、eval-045。它们与旧基线“操作性转交不形成单独承诺”的边界重叠；原 P1 标签不变，不能用删除误差统计解决。

在 C++ 关系目录和准入指导中排除附带的操作性路由安排；必须保留明确的 settled choice，例如“我已经决定采用第二条升级路线”，以及有明确决定语义的转交选择。不能按 `route/forward/转交` 全局关键词拒绝，不能把同话轮其他路由句当成候选主体关系。优先澄清提示；仅在独立正反例证明安全时增加候选局部确定性规则，所有路径共用 C++。不在 Python 重做该判断。

### 关系否定与转述

固定正例 `new_en_negation_yes` 当前被语义拒绝；`new_en_attribution_yes` 的格式失败原文还显示模型误读情绪否定。以独立来源分别测试“否定情绪关系”与“含否定词的情绪对象”，保留已有 polarity/scope 契约，不添加自动纠正。技术失败样本即使内含 reject 也不能计入正确负例。

## Q1/Q9 的原生时间证据视图

Q1 两条来源分别是反对增加建筑体量与把交通危险关联到发展；需要基础判断/行动及父来源聚合，情绪词数量不能代替立场依据。Q9 早期原话为“swindon. not decided yet”，晚期为对重新开始的紧张和停滞感；本轮 Marcus 补充抽取因重复键整批未入库，必须先通过协议和语义修复让目标声明稳定保存。

已实现默认关闭的原生 `TemporalEvidenceRequest` 及 `TemporalEvidenceView`，作为 Retrieval 的证据选择接口，生产语义仍在 C++；真实对照仍以目标声明能够稳定入库为前提：

```cpp
struct TemporalEvidenceRequest {
    std::string tenant_id, actor_id, topic;
    std::vector<std::string> ordered_session_ids;
    std::string through_session_id;
    int limit = 10;
};
struct TemporalEvidenceCandidate { StatementRow row; double score; };
// 输入已经通过权限、来源合法性和查询相关性筛选的可见记录。
// 输出 Statement 引用、来源顺序、主题歧义和证据不足原因，不生成新的事实。
TemporalEvidenceView select_temporal_evidence(
    const std::vector<TemporalEvidenceCandidate>& visible_candidates,
    const TemporalEvidenceRequest& request);
```

`ordered_session_ids` 来自请求许可的来源会话顺序，不能按 session 字符串排序猜时间。生产调用者从已摄取元数据或查询约束提供；Python 只映射字段，不比较状态、排序或选主体。通过会话必须出现在列表且列表无重复，否则失败。未列入请求、晚于截止、跨 tenant/actor 或证据失效的记录排除。相同会话按合法原始 turn_index 排序，缺失顺序显式报告；不把 observed_at 伪造成状态事件时间，不用未来记录补齐过去。

选择器接在现有 C++ 过滤/重排之后、最终 top-k 截断之前，输入显式携带原生 score；不能只重排已经丢失早期证据的最终 10 条。候选搜索沿用原生预算，范围不足时报告不足，不用全库无界扫描补齐。topic 不明或多义时报告歧义，不能从金标借用主题。对通过筛选的记录，在总数上限内保留最早与最后来源各一条，再用既有相关性得分补齐；相同得分按 tenant/id 稳定排序。仍不足两端、limit 小于 2、或仅一条来源时返回证据不足，不能声称发生变化。重复按 `(tenant_id, statement_id)` 去重，不能扩大可见性；相反状态并存时保留引用，不自动裁决。旧记录缺少可核验的来源顺序时单列缺失，不能补造 source_turn。

视图只提供早晚证据及原因。对“寡言到坦诚”等解释，回答必须用多条父来源并标注为推断，不写入已认证直接 Statement。`full` 组仍是全文上限对照，不能当作 Starling 实际检索成功。四组 Q1/Q9 各自报告入库数、目标 actor 入库数、早晚命中、链接数、截止违规、回答及裁判票。

该视图单独做测试与实验；若协议阶段被 capability_blocked，时间逻辑可继续本地测试，但不能报告新模型质量。若目标人物仍无法入库，则停止真实时间视图比较并报告前置失败，不以空结果冒充算法比较。

## 分阶段验收与默认

### 时间视图实施约定

主题采用来源已认证 `topic` 与请求主题的精确匹配，不增加跨语言语义归并或从答案补主题。空主题、无效/重复会话顺序、缺失截止和不足两条不同来源位置均显式报告不足；小于 2 的预算不返回变化证据。选择范围是已可见的有界候选集，不能保证全库的绝对最早/最晚来源。默认不调用选择器，Context Pack 字节保持旧路径。

纯选择器只接收已获授权的候选，复查 actor/tenant、来源顺序及两份来源引用的一致性；实际原始载荷与哈希由 Planner 已有 `claim_evidence_error()` 在选择前核验，不在无数据库参数的接口中伪造第二次认证。新增 Planner 集成测试覆盖原始来源篡改和最终 top-k 前的两端保留。输出只读引用与不足原因；来源顺序不推断事件时间或状态变化事实。

协议阶段固定语义；语义阶段固定可用输出模式；时间视图阶段固定声明库及基础检索。每阶段用独立目录/源码/输入哈希，报告变动来源和服务端不确定性，不将单次提示收益包装为确定因果。

必过门槛仍是 64 固定候选零技术失败且全对、16 synthetic 逐例不退步、50 P1 兼容、基础语义未改写、Q1/Q9 证据人工复核。补充正反例不进入这些原分母。时间视图另要求截止/跨 tenant 违规为零。生产 `semantic_claim_contract` 和时间视图开关默认关闭；任何一项未过不运行 1,031 题全量。
