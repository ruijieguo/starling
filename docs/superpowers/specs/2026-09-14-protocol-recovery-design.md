## 已确认事实与未决原因

1. 原 8 条 DashScope / `deepseek-v3` 请求全部 HTTP 200，但两个模式、两个契约共四组均 `nonconformant`。正常案例同样失败；不能只归因于冲突格式指令。
2. C++ 请求构造与本地捕获预览均包含正确的 `response_format`。JSON Object 请求的提示包含 JSON 关键词；严格请求包含 `name`、`strict=true` 和完整 schema。目前没有证据表明 Python 丢失参数。
3. **确定的本地缺陷：提示示例与严格 schema 不一致。** A、B/C 的抽取提示各有 6 个示例，全部缺少 schema 必填的 `confidence`。用原生 `structured_output_validation_error()` 校验均报 `schema_failure:missing_field`；只在示例副本加入 `confidence:null` 后全部通过结构检查。此诊断没有修改真实响应，也没有证明围栏失败由这个缺陷造成。
4. [官方结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)区分 JSON Object 与 JSON Schema，前者不保证字段结构。JSON 关键词可以位于 System 或 User Message，没有必须设置 system 消息的要求。当前支持表没有列出旧标识 `deepseek-v3`；其中 `vanchin/deepseek-v3` 是不同模型标识和部署来源，不能当作原模型支持证明。
5. 同一官方支持表列出 Qwen3.7-Plus 系列的严格 Schema 支持；[模型目录](https://help.aliyun.com/zh/model-studio/models)提供确切名称 `qwen3.7-plus`。这只支持把它列为实验候选，不能保证现有账号、地域和旧端点已经可用，也不能证明它满足 Starling 的全部 schema 子集。
6. 服务内部是否忽略旧模型的格式参数尚未证实。本地问题、公开文档支持范围和实际观测分别归档；不把“未列入支持表”改写为原生 Unsupported。

## 方案比较与推荐

| 方案 | 收益 | 限制 | 本轮取舍 |
|---|---|---|---|
| 仅修复提示并再次请求旧 `deepseek-v3` | 保持模型相同 | 没有新增服务能力依据，仍可能反复得到围栏；修复 confidence 不能保证裸 JSON | 不作为首选真实实验 |
| 修复共同提示缺陷，再显式选择文档列出的同服务模型 | 修复确定缺陷；以独立 A/B 对照分离关系修复效果 | 新模型结果不能冒充旧 DeepSeek 分数提升；需要新能力证据 | **推荐：`qwen3.7-plus`，同一 DashScope 端点，严格模式** |
| 剥离围栏、提取中间 JSON 或回退自由文本模式 | 能减少表面解析失败 | 改变验收含义，不能证明格式约束生效 | 不采用 |

推荐方案分两部分：C++ 修复提示契约；评测层显式选择模型并严格绑定实验身份。暂不改变消息角色、探测案例、重试策略、schema、谓词定义或生产默认。

## 配置与绑定职责

`scripts/eval_socialmem_extraction.py` 的既有构造入口接受显式 `model` 配置，默认仍为 `deepseek-v3`。`probe_socialmem_output_capability.py` 和本轮 claim 评测 CLI 增加 `--model`，将值转交原生 `OpenAIAdapterConfig.model`，归档实际配置并在启动前与能力报告核对。

Python 只负责参数、编排和身份核对。请求体、schema、能力判定、原始回执和重试仍在 C++，不会按模型名在 binding 中复制协议逻辑。空模型名在发请求前拒绝；不遍历模型、不自动换 endpoint、不读取或展示凭证。旧 CLI 不传新参数时保持原行为。

从本次起新实验显式记录以下不同身份：

- 新抽取/准入模型及端点；原生核心、共享修复、关系提示和 schema 哈希。
- 冻结基础记忆原模型及父归档；它仍来自旧 DeepSeek 结果，不因新请求选择 Qwen 而改名。
- 回答/裁判模型和端点；嵌入模型和维度；各通道逻辑调用与实际传输次数。

模型响应原文已经保存返回的 `model` 字段；分析保留请求名与服务返回名，不能擅自替换为假定的版本快照。历史 manifest 不补造字段，新验证器兼容既有档案边界。

## A/B 实验身份和能力有效期

定义 A′、B′ 仅用于本设计说明：A′ 为已冻结 A 加共同修复，B′ 为已冻结 B 加相同修复。真实档案保存完整哈希及父归档，不能只依赖这两个简称。

1. 使用独立可写的实验副本从 A、B 各自冻结源码生成新版本；旧 `source_archive` 和 `.so` 不修改。新 A 不包含 B/C 的新增关系或时间选择实现。
2. 每个阶段单独构建、验证、生成请求预览并冻结核心；共同修复 diff 保持相同。
3. **原计划每核心探测最多 8 次；用户此次仅额外批准 A 因报告过期刷新同样 8 次。** A 获批两轮合计 16 次，B 原计划仍最多 8 次，不由 A 的刷新批准推定 B 可刷新。原报告、新报告和过期原因分别保留；刷新不是自动重试。另有前一轮误调用的 8 次 DNS 失败，属于额外操作偏差，必须计入实际探测尝试，不能以本次预算调整追认或删除。报告包含完整核心哈希和该阶段提示；不得改写 A 哈希用于 B。
4. 每阶段探测结束后立即核对报告和实际目标配置；严格模式抽取、准入两个契约均通过，且报告在运行开始时未满 10 分钟，才开始该阶段 cohort。运行中不因 TTL 自动追加探测。
5. A 严格门槛不通过时停止全部真实流程，不发 B 的 8 次请求。B 门槛不通过时保留 A 的独立结果，B 质量为空；不能报告 A/B 语义增益。
6. JSON Object 同属 8 次探测的诊断臂；即使其通过，严格模式失败也不自动使用它运行 cohort。

探测版本、通用 Nora/picnic 来源、正常/冲突案例及原 schema 保持；变化的提示与模型由新核心和请求预览哈希记录。历史失败报告保留原观察时间和原分类。

现有 A/B `source_archive` 含生产源码与评测固定数据，但没有完整 C++ 测试树，不能声称从它单独恢复了原全套测试。当前开发版本执行完整套件；阶段副本明确登记额外复制的公共测试夹具和新增协议回归测试的来源、哈希及适用范围，分别构建验证。A 不运行仅属于 B/C 的语义/时间测试；阶段聚焦验证不能冒充当前版本全系统回归。

## 新真实实验的发送范围与预算

此前自动审批拒绝的原始 A 探测已获得明确授权并执行；用户随后明确授权 A 诊断和一次过期刷新，A 已在刷新报告有效期内启动。B 尚未执行，不能由 A 的专门批准推定新的 B 刷新预算。下表定义通道范围和条件，实际计数另含报告中明确记录的操作偏差。

| 通道 | 目的地与模型 | 输入 | 上限与条件 |
|---|---|---|---|
| A′、B′ 能力探测 | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`；`qwen3.7-plus` | 原通用来源、对应阶段提示、schema；无评测问答金标 | A 首次 8 次 + 本次获批刷新 8 次；B 原计划 ≤8 次。均零重试；A 能力失败不启动 B；额外意外失败单列 |
| 每阶段补充抽取/准入 | 同上；`qwen3.7-plus` | 已冻结评测来源及待验证候选；模型不可见评测问答与标签 | 140 条记录：76 抽取、≤140 准入；沿用 ConnectOnly 和已归档配置的重试上限，次数另计 |
| 每阶段回答/裁判 | 既有 `https://api.tokenkey.dev/v1`；`gpt-5.5` | 回答使用问题与允许上下文；裁判按原协议使用参考答案与候选 | 每阶段 8 回答、120 裁判票，分别 512/8 输出 token；保持原重复票规则 |
| 每阶段检索嵌入 | 既有 `https://api.tokenkey.dev/v1`；`qwen3.7-text-embedding`，1024 维 | 原固定 QA 检索的文本/查询 | 沿用固定 QA 日程及既有分批配置，记录 request/embed/batch 计数；历史 19 请求仅供参照，不冒充新运行固定预算 |
| 条件时间 QA | 同一既有回答/裁判服务 | B 目标人物稳定入库后的核验副本与时间视图上下文 | 满足原条件后最多 4 回答/12 票，独立归档；不用新抽取 |

能力探测每请求继续使用 `max_tokens=4096`、`timeout_ms=60000`、温度 0。服务拒绝模型、要求新地域端点或拒绝 schema 子集时保留原文并停止，不自动迁移 API Host、替换账号、改变 schema 或追加请求。正式 cohort 的网络失败保持既有逐次证据规则。

新目录使用 `build/socialmem_20260914_protocol_recovery_a_real` 和 `build/socialmem_20260914_protocol_recovery_b_real`，能力报告分别保存在独立路径。父输入仍是 `build/socialmem_20260910_supplement_run`，不得改成缺少 `prompts.json` 的后续结果目录。
