# Python 日常回归与历史回放边界修复

## 目标与授权

用户在全面回归、dashboard 重启与样例验收报告后要求继续。本轮沿用报告提出的方向：修复测试对已退役实验产物的耦合，使日常回归可重复执行；保留历史回放及其失败证据。顺序为中文设计、失败测试、实现、回归。核心产品规则仍在 C++，本轮仅调整测试输入和执行组织。

## 诊断

上一轮完整 Python 首次执行为 2405 通过、117 失败、450 报错、15 跳过。专项复测后剩余 557 项受历史文件、构建身份或实验契约影响。另有当前原生模块与冻结原生模块同进程混用，引发来源门禁拒绝。不能以重写旧 SHA、放宽校验或恢复已退役的大型实验目录处理。

## 方案

1. 将仅使用配置字典、人工对话或少量脚本文件的测试改为自包含夹具。夹具使用手写的协议字段和人工样例，不保存历史预测、数据集原文或大型数据库；断言继续调用真实验证器、C++ binding 或本机 HTTP 服务。
2. 真正需要固定历史语料、sealed 数据库、历史二进制和实验身份的用例显式标记 `historical_eval`，原因说明其依赖。按依赖标记，同文件中的纯逻辑与临时夹具测试保留日常执行；共享测试函数继承相同标记。
3. 默认 pytest 在收集阶段将这些历史用例报告为跳过，确保其 fixture 不执行。`--run-historical` 明确恢复执行，既有缺失文件、SHA、来源及语义门禁照常报错，不能自动转成成功或 xfail。未知标记视为错误，避免拼写错误隐藏分类。
4. 历史回放按文件使用独立 Python 进程执行，避免同时加载多个版本的原生模块。先用仍可核验的冻结 baseline/上下文审计验证成功路径，再用已退役历史用例验证显式执行仍失败的路径。
5. 默认执行结果必须同时报告通过数、历史跳过数、原有跳过数。默认回归通过不等于历史回放通过，不产生新的 SocialMemBench 分数。

## 备选与取舍

整体排除所有 SocialMemBench 测试会丢失当前编排和能力回归；恢复全部已删除产物违背清理要求；按上次失败列表自动跳过则会掩盖真实回归。本方案依据测试代码的输入依赖逐项标注，同时恢复自包含覆盖。

## 测试与实施步骤

先新增 pytest 子进程行为测试，验证默认历史 fixture 不会执行、显式执行保留真实失败、同文件普通用例仍执行、普通失败不被抑制、历史标记通过函数复用传播。然后运行原有缺失配置等用例记录 RED，再实现小型夹具和历史标记。

回归执行完整 Python 默认套件、标记与入口行为测试、自包含迁移用例、可用历史用例的独立进程验证，并验证不可用历史用例仍失败。C++ 与前端只有在产品代码变化时才重测；dashboard 保持在线，完成前复核健康。

## 长进程资源隔离补充

完整默认套件出现六个 localhost HTTP 失败，但单独执行相关两文件为 21 项通过。按测试前缀复现，HTTP 前进程已持有 1037 个描述符，`lsof` 显示大量来自已结束用例的临时 SQLite 数据库。对照诊断在首个 HTTP 用例前执行一次 `gc.collect()`，该次描述符从 1110 降至 124，相同前缀从 3 失败、1408 通过变为 1411 通过。原生回执在故障时为 `transport_error:A libcurl function was given a bad argument`；未修改网络实现或吞掉异常。

为避免日常回归依赖 Python 自动循环回收的触发时机，在每个测试的 fixture teardown 全部完成后收集不可达循环对象。此钩子仅属于测试基础设施，不强制关闭仍被持有的连接，也不改变产品生命周期；新测试仍应显式关闭自己创建的数据库连接。先添加独立 pytest 子进程回归：测试 A 的 fixture teardown 遗留一个持有连接的不可达环，测试 B 必须观察到其 finalizer 已运行。该用例关闭自动 GC，以验证结束钩子的顺序和效果；不得把故障 HTTP 用例标成历史回放或跳过。

## 文档与产物（验收）

更新 pytest 配置、测试说明、当前回归报告及相关 dashboard 设计入口。保留本轮日志、JUnit、历史依赖清单和明确失败的显式回放证据，清理临时副本。上一轮结果按其执行时点保留，不回写历史分数或 seal。

## 最终验收

完整默认套件 2385 通过、609 跳过、零失败或报错；跳过包含 594 项历史回放和 15 项既有跳过。仍可核验的三组历史回放在独立进程中共 14 项通过；已退役 R6.8 用例显式执行仍失败，失败未被抑制。主、样例 dashboard 共 39 项 API 复查通过。144 份现行设计文档同步本边界，历史快照保留原文。详细证据、资源压力诊断和清理结果见[验收报告](../../eval/2026-09-27-python-regression-boundary.md)。
