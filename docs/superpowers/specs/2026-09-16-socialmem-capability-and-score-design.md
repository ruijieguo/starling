## 目标与成功标准

最终交付是能在 SocialMemBench 上稳定取得高分的 Starling：正确记住人物、事件、态度与关系，保留跨会话变化，按问题找回足够证据并完成回答。协议通过率、单元测试、候选数量及局部契约指标用于定位问题，不能替代真实问答成绩。

按以下层次验收，不预先编造绝对得分承诺：

1. **首轮可测收益**：在冻结开发集上，用相同模型、回答提示、数据范围和记忆上下文预算，比较当前 Starling、新 Starling、带说话人/时间信息的 RAG、全文对照；交付逐题结果和失败归因。开发集提升至少 10 个百分点作为首个迭代目标，不是已取得的结果。
2. **能力收益能够推广**：在未用于实现和调参的网络级保留集上，新 Starling 同时超过当前 Starling 和同预算 RAG。按网络做配对重采样，报告差值及 95% 区间；区间不能区分优劣时如实报告不确定，不能只凭点估计宣称胜出。
3. **正式成绩**：冻结最终实现，运行本地全部 1031 题并报告总体、Q1–Q9、回答格式及跨人/跨会话分组结果。全量包含开发题，必须与保留集结果分列；确认评分协议与基准标准一致之前，只称本地评分，不称官方或榜单成绩。
4. **保留记忆系统的价值**：同步报告召回上下文 token、写入成本、查询成本和延迟。全文对照是独立参考，并非理论上限；同预算 RAG 是主要效率与质量对照。不能靠扩大 Starling 上下文而隐去成本差异。

若全文对照也答错，优先核查时间范围、题目解释、回答模型和评分；若全文能答而 Starling 失败，沿记忆链定位。不得把所有错误都归于缺少谓词。

## 技术路线选择

**采用：带结构的社会记忆与原始来源共同提供证据。** 结构支持人物、关系、范围、时间及查询选择；来源话轮保留结构未表达的行为细节，支持可核查的回答。通过消融区分仅结构、来源检索、两者结合的增益。

只增加封闭谓词枚举无法解决上下文丢失、归属和时间证据不足。直接把所有历史交给回答模型能作为对照，但不能替代 Starling 的记忆能力建设。因此不把二者作为单独主线。

### 1. 基线完成后按实际缺口处理原生协议兼容

在 C++ 明确区分完整本地 schema 与提供商请求 schema。给 provider profile 独立版本与 wire hash，本地仍严格校验非空、重复、主范围和来源；能力回执同时绑定两种 schema、profile、模块及配置。第一版 provider profile 沿用已有实际成功记录的 C0 wire 结构，不向服务端发送 minItems/uniqueItems，但保留新 C++ 本地的两项检查和原生范围语义。此选择在请求前明确固定，不在失败后自动删字段或换模式。

minItems 单独兼容性仍未知，暂不为它单开优化轮次。首轮只对上述一个明确 profile 做最多8次能力探测，通过后用同一配置连续进入真实写入/召回/回答。必要约束由 C++ 完整校验兜住；若空标记导致实际候选损失，在端到端失分归因中按生成/协议错误计数，不回填内容。旧 C0 成功记录不代替新模块自己的能力验证。

### 2. 查询无关的连续写入与完整来源

按网络、会话、话轮顺序保存 speaker、turn_id、session 顺序和来源时间。C++ 负责语义窗口及来源定位；窗口按会话/大小切分，可带固定相邻上下文，记录重叠来源并去重。不能把同一人的所有话一次拼成无时间长段，也不能为了回答某道题才选择其金标话轮写入。

写入继续使用 prepare→extract_all→commit_all 的原生路径。每个 holder 明确限定可写的主体/视角，邻人话轮只作上下文时不能变成该 holder 的直接状态。长输入、某一窗口抽取失败及部分成功均保留统计。每个网络/截止快照独立，按内容与配置哈希复用写入，避免每题重复烧抽取费用；更换抽取配置时重建对应记忆版本。

基础事实、事件和补充社会状态共同进入可检索记忆。需要新增关系时，先展示旧表示无法保留的区别，再给独立来源的正反例、字段与迁移契约；不从某一道题的参考答案倒推专用谓词。

### 3. C++ 统一人物范围、证据选择和上下文预算

将通用评测中的跨 holder 选择收进可供所有 binding 调用的 C++ 接口。输入必须是显式授权的观察者/holder 范围；多人物测试不能等同于扫描租户全部私有记忆。候选统一过滤、评分、去重和截断，Python 不再复制排序及语义选择规则。

按问题确定人物、主题、时间边界及证据需求；这里允许使用真实用户问题，禁止使用参考答案、证据锚点或基准 Q 编号作为隐藏路由。先复用当前 Planner 与时间证据视图，覆盖早晚状态、相反意见和关系两端。证据不足要在回执中可见，而非静默扩大权限或取截止后的内容。

在同一上下文预算内组合结构声明与经 C++ 认证的来源片段。来源选择必须具有独立的召回入口：某条内容未被抽成 Statement 时，仍可通过原始事件/话轮证据找到，避免结构漏抽使原始来源永久不可达。所有来源都经 tenant、可见性、时间和哈希检查；是否最终采用此入口以对 RAG 和结构路径的消融为准。

### 4. 基于证据回答，保持推断边界

回答上下文携带人物、来源顺序、直接/转述/推断标签及来源引用。将“较早状态→触发事件→较晚状态”“群体决定与个体异议”等组织为通用证据结构。允许回答模型根据多条行为证据作推断，但不将推断伪装为直接抽取事实或自动写回已认证记忆。

回答与裁判模型在配对实验中保持一致；如改用更强模型，单列模型因素。不能把换模型收益归给 Starling 的表示/检索改进。

## 首轮实验与评分设计

先审计以往实验、提示和调试访问过的网络；开发网络与保留网络分开。已阅读题目元数据的语料不能笼统称为从未见过；保留集准确名称是“未用于实现调试和结果驱动选择的网络”。若无法可靠核实历史暴露，公开标记限制，不能包装为严格未见测试。

第一轮首先冻结全部 1031 题并运行当前默认 Starling 单臂基线。基线完成后，能力开发可采用原拟 48 题分层规模：Q1/Q8 各 10、Q7 8、Q2/Q4/Q5/Q6 各 4、Q3/Q9 各 2；具体清单按真实失分和网络隔离确定。题目选择依据网络、题型、格式和来源跨度，不能按已知对错选题。网络隔离优先于精确配额；先输出可满足性与固定清单，若不足以覆盖则调整清单并记录，不偷用保留网络。

四个主臂：当前 Starling、新 Starling、同预算 RAG、全文对照。正式比较使用新冻结的基线，历史 22 题成绩只作背景。RAG 保留相同人物和时间元数据；全文须遵守同一可见时间范围，明确其额外上下文成本。诊断 oracle 可离线核查错误来源，但不进入正常系统输入、不混入总分。

每题依次记录：来源存在→抽取候选→原生保留→入库→可见→召回→上下文证据→回答。将错误归入传输、表示缺失、抽取遗漏、误拒、归属、时间、检索遗漏、上下文截断、回答推理或评分争议；一题可含多项，贡献分析不能直接相加。题目锚点只用于离线证据召回统计，不能充当所有合法证据的完备集合。

MC 按确定性选项解析计分；自由回答沿冻结裁判协议计分并保留原票。评分协议与基准标准的映射需先核实，重复同模型投票不声称独立裁判。参考答案、选项正确标记、锚点及 persona 隐藏设定仅供评分/分析，不进入记忆写入或普通检索。

技术失败、空回答及未完成项留在原分母；只补做明确未发送的请求，不根据得分重试。报告已完成比例与失败原因，同时给出按题型的宏平均，避免只优化大题型掩盖小题型退步。保留集的检验采用一次冻结候选；查看结果后继续修改的网络要转为开发用途。

### 预算与执行节奏

当前全量基线按[执行计划](../plans/2026-09-16-socialmem-baseline-first.md)设置 25000 次原生 HTTP 保守上限，并发最多 4；先完成前两个来源范围组，再连续执行其余组。来源限定不同的题按 network 与历史哈希分库。抽取、检索、回答及裁判使用冻结配置，原生传输零重试，Extractor 内部逻辑尝试照当前实现执行并单列。

原拟 1224 次、48 题四臂方案已被最新先基线要求替代，不是本轮可滚用余额。后续候选每轮依据实测成本冻结有界预算，再在用户已授予的自主迭代范围内执行。不得在失败后静默改变模型、题集或来源范围；用户目标不是无上限重复请求。

正常语义错答是诊断结果，应完成其余已授权样本，不能因为 64 个控制未全对便禁止获得端到端开发分数。隔离破坏、输入污染、固定计划漂移或所有请求均因 schema 无法执行时才停止依赖阶段。生产晋升继续使用严格门槛，与允许开展带失败的开发评测分开。

## 文档、测试、实现与评测顺序

| 步骤 | 文档与失败测试先行 | 实现/实验输出 |
|---|---|---|
| B0 当前版本全量基线 | 固定当前核心、1031 题、默认路径、来源范围、评分及预算；编排先测试 | 真实逐题成绩、技术失败、Q1–Q9 汇总，保持失败分母 |
| M1 补齐最高收益能力 | 依据 B0 的开发网络失分，先中文专项设计，再独立失败用例 | C++ 实现；若启用补充契约才先处理 provider profile |
| M2 同条件复测 | 固定题集、模型、来源范围与评分，候选独立冻结 | 配对正确题增减、网络重采样区间、成本和退步分析 |
| M3 继续迭代与保留验证 | 有收益的候选进入下一轮，保留网络不逐题调参 | 最终全量与未用于改进的网络结果分列；无收益候选不晋升 |

完成基线是后续优化的前提，不能把协议测试或离线全绿作为成绩。RAG 与全文对照按失分归因需要加入，使用相同允许来源范围；其分数与当前 Starling 基线分列。

2026-09-17 运行中观测首先暴露大量写入超时。基线完成后按[生成可用性诊断设计](2026-09-17-socialmem-generation-availability-design.md)先用固定开发样本恢复完整回执，再选择有证据支持的单变量改进。该专项已完成10次生成诊断及6题实际试跑、6题固定记忆巩固对照；接续原始来源保留和原生检索，不把技术恢复冒称全量能力提升。
