# SocialMemBench R4.0 证据覆盖与原生回答设计

日期：2026-09-21。状态：已完成文档、失败测试、C++ 实现、离线验证及真实双臂评测；两臂均 19/57，未达开发继续门槛，不晋升生产。所有核心选择、证据解析和提示在 C++；Python 只映射、编排和统计。

## 1. 当前依据与实验边界

R3.5 固定 57 题、7 个范围、6 个网络，16/57 正确，问答技术失败 0；35/36 holder 完整，1 个范围为 partial。与 R3.4 的 48 道共同正常题均正确 12 题，未证明语义提升。上一轮通过字符串片段估计的 53/104 不是严格来源召回率：SOURCE 展示不含 turn_id，结构化转述也不能仅凭子串否定。R4 改用原生 source_refs 与公开 anchor 的 turn_id 精确关联，区分完整原话命中和声明回指；锚点仍不是完整答案要点。

代码核查发现：focused_coverage 先选择最多 10 个来源，再按时间排序，hybrid 只取前 7 个，因此晚期证据可能二次丢失。人物轮询还会为跨会话覆盖选择会话第一句，与具体主题弱相关。R3.5 使用 legacy 自由回答；已有 grounded/synthesis 接口仅接受 sources。历史 synthesis 和双阶段证据规划均未晋升，故本轮复用 grounded 规则，不启用额外规划请求。

## 2. 选择与备选

采用新策略 evidence_profile_v2：在最终来源名额内选择，再按时间展示，保留可审计的覆盖车道。相比继续扩大 k 或回答容量，本轮固定 k=10、8000 字节、回答 512，便于判断来源组织是否有效。相比新增 LLM 规划，确定性选择不增加解释锚定或生成失败。本策略是检索启发式，不是人物关系、行为反例或因果语义识别器。

## 3. C++ 选择契约

ObserverQuery.source_strategy 显式接受 evidence_profile_v2，默认 bm25 不变，旧策略逐字保持。权限、租户、holder、截止时间、擦除、来源哈希和话轮去重仍在候选生成之前执行。

复用现有姓名完整边界匹配；只从问题文本和 allowed_holders 推导关注人物，不接受 query_type、题号、参考答案或锚点。问题中的时间变化/早晚词触发时间车道，关系/回应或多人物触发互动车道，跨会话/重复行为词触发行为覆盖车道。未知问题使用相关性回退。

来源名额在获取 statement 候选后计算：sources 模式为 k；hybrid 为 max(min_source_items, k - min(statement 数, k - min_source_items))，min_source_items=0 时使用原交替分配对应的来源份额。有足够 statement 时 R4 仍为 7 SOURCE + 3 statement。来源只选择这个名额，不选 10 后再截成 7；字节预算按完整 UTF-8 行计数。先选相关性种子，再轮询激活车道，最后相关性补足，最终一次按陈述时间展示。

车道规则：

- 相关性：以原 BM25 排序为底座，优先关注人物发言或明确提及关注人物的第三方发言；关系问题优先一名目标提及另一名目标的发言。无目标人物匹配时保留全局候选回退。
- 时间：关注人物相关候选按可定位会话分组，每会话选择相关性最高的候选，按早、晚、中间顺序轮询；同一个来源只能占一个位置。此版本不保证每个人物独立覆盖全部时间段。时间未知的来源可参与其他车道，不用于早晚覆盖证明。不以 session 字符串字典序代替有效陈述时间。
- 互动：目标人物之间的明确提及及高相关种子同一 session 内的连续邻句；严格服从 source_dialogue_radius，缺失位置不跨越，不跨 session。第三方叙述保留其真实 speaker。
- 行为：按未覆盖的人物/会话补充相关来源，可保留相反表述；这里只追求来源多样性，不自动标记为“已确认重复行为”或“已确认反例”。

receipt 增加 profile、各车道目标名额/实际入选、每条候选的选择车道、预算拒绝、最终 rendered 标记、已覆盖人物/会话及缺口。semantic_verified=false；覆盖缺口不等于问题不可回答，禁止把时间两端视为因果充分。最终回执集合必须等于真正进入 block 的 source_refs。

最终渲染先输出已选来源，再用剩余条数和字节容纳声明；不再从未入选来源池补行。来源中的 everyone 等泛指词不算明确人物提及。新策略透传原生 degraded_paths，评测遇查询降级记为失败，防止把服务失败混入正常检索结果。

## 4. 原生回答边界

新增 grounded_memory_answer_packet(question, recall_json) 与 grounded_memory_answer_prompt(question, recall_json)，策略名 grounded_memory_v1。C++ 将 ObserverRetriever 的 SOURCE 和带标签 statement 行组成无损证据包：保留原文、speaker、session、时间、来源引用和 statement 身份；原生严格解析来源行、验证行数/标签/引用数量及归属，不从说明文本补写事实。坏格式、空白问题或相互矛盾的回执在模型调用前拒绝。

包明确区分原始对话与派生 statement；派生关系不是人物原话，不凭其存在声称双方互动。coverage 只包含本次已渲染来源的计数与缺口，不携带未选原文，semantic_verified=false。复用 grounded 的逐问回应、主体归属、前态/触发/后态、引用与限定规则，并提示可作有证据的有限社会推断，避免把一个缺口变为整题拒答。单次回答，无规划、重试或答案修补。

Python binding 只导出两函数；run_socialmem_baseline.answer_prompt 只增加该政策路由，允许 sources/hybrid，拒绝 statements/full。选择题仍调用冻结 legacy MC 提示。新增字段不改变生产默认。

## 5. RED 测试与工程验收

原生夹具使用独立人物与主题，不写入基准人物或答案。覆盖：晚期来源不被最终截掉；会话内主题句优于寒暄；双向回应和第三方归属；重复行为不同会话；未知时间、姓名边界、禁止越权/未来/擦除来源；UTF-8 整行预算、空候选及确定性；trace 与 rendered/source_refs 一致。回答接口测试混合来源/statement 无损、Unicode 伪分隔符、错误标签/引用/空白问题拒绝、空来源保持未知、不把未入选原文带入提示。

Python 只测真实 binding 与政策路由、旧 MC 提示相同、非法配置和实验身份/预算/完整分母门禁。先保存 RED，再实现 GREEN，运行相关 C++/Python 和完整 CTest。网络相关 loopback 测试在允许的本地环境验证或明确列出跳过。
