# 显式人物与相邻话轮检索设计

状态：C++实现、离线消融与733题真实复评完成；273/733=37.24%，相对k30+10.37百分点，保留集119/298=39.93%，全量392/1031=38.02%。用户已授权自主迭代与 DashScope 请求。

## 问题与目标

固定733道开发题，正文BM25的k10为153/733，k30为197/733（26.88%）。k30公开证据锚点命中560/1353，仍有293题零命中。第一人称发言不一定含说话人姓名，题干中的姓名无法通过正文BM25可靠召回本人证据。此前把姓名拼入正文的57题实验未改善，不能重复当作已验证方案。

本轮增加原生的显式人物路由，保持k30、8000 UTF-8字节及模型/提示词/评分一致。离线只比较两个预先确定的候选，随后冻结一个候选完整评测733题。298题保留集不参与选择或逐题调参；离线锚点召回不是问答准确率。

## 接口与算法

`ObserverQuery.source_strategy`新增字符串字段，默认`bm25`，只接受`bm25`、`focused`、`focused_window`。后两者仅适用于`mode=sources`，其他组合抛出参数错误。默认路径须逐字复现既有block及source_refs。Python只暴露字段、透传参数、编排实验，不实现人物识别、排序、邻接或预算逻辑。

1. 先运行既有tenant、allowed_holders、登记/观测时间、擦除、保留策略、哈希校验及去重过滤，再做排序。新策略不能重新访问未过滤来源。
2. 从题干匹配显式allowed_holders中的完整姓名，大小写精确、左右字边界，允许所有格；不推断别名，不读取选项、参考答案、题号或证据锚点。重叠姓名优先最长匹配，再按题干位置确定人物队列。ASCII字母/数字/下划线及非ASCII字节视为词字符；中文连写姓名暂不推断。`will`不匹配`Will`，但句首同形普通词仍可能误路由，这是已知限制。
3. 各被点名人物的已过滤发言按原BM25顺序建独立队列，按题干顺序轮转。全局队列保持原BM25顺序。`focused`以“人物、人物、全局”的次序选取。人物队列耗尽后全局补足，保留第三方证据。
4. `focused_window`以“人物、人物、邻接、人物、人物、全局”的次序选取。邻接队列来自实际选中的人物发言，只扩展相同非空session且数值turn_index恰好±1的已过滤来源；不跨session、不猜缺失索引，前一轮优先于后一轮，同索引冲突按原BM25顺序。队列为空时回退全局，再回退人物。所有通道共享去重及预算。
5. 每次选取跳过已选或装不下的完整来源，继续寻找能装下的来源；同时受k和UTF-8字节预算约束。不截断原文，不切坏字符。人物轮转按实际成功选取推进，单个人物耗尽不阻塞其他人物。
6. 激活人物路由后，选中的来源按观测时间、session、数值turn_index、稳定identity排序渲染；未知观测时间置后，不伪造时间。block与source_refs始终同序，诊断显式记录策略及命中的人物。
7. 无姓名匹配或被点名人物无合格来源时回退原BM25，block、refs、原有诊断保持相同。结构与hybrid路径不改。
