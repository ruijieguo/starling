# SocialMemBench R4.8 同一声明状态资格设计

设计日期：2026-09-23；完成日期：2026-09-24。状态：先文档、RED、C++ 实现及独立复评已完成。R4.8 检索 18/57、原生回答 17/57，0 技术失败；未证明 QA 提升，不晋升。详见[中文诊断报告](../../eval/2026-09-24-socialmem-r48-state-claim-identity.md)。

## 问题与目标

R4.7 的 v6 状态车道先用 `state_marker(source)` 判断状态语义，再用另一个 `any_of` 判断 actor 等于 speaker。多 claim 来源可能由不同 sibling 分别满足两个条件。另一个入口是文本词 `now/after/prefer`：即使来源只有非状态 claim，也可能凭词语获得状态车道优先级。两条路径均需先由原生失败测试确认。

目标是让状态车道的 family、actor、source_turn 条件绑定到同一条已通过原生证据合同的 claim。对每条 claim 同时要求：

1. family 属于现有状态集合：preference、plan_decision、affect、uncertainty、behavior、belief；本轮不扩充集合。
2. actor 等于来源 speaker，并具有有效 source_turn；来源与声明回连/授权校验沿用既有合同。
3. 上述条件不得由另一 sibling 或原文关键词补齐。来源有任意一条完整合格 claim 即可进入，但只占一个名额。

`knowledge` 和 `ownership` 在当前状态集合之外；它们仍能进入归属或普通相关性检索，不因含“now/after”自动代表状态变化。未合格的来源仍可由其他车道选择，不能把不进入状态车道解释为删除记忆。

## 方案取舍

选择在 C++ `profile_sources` 内统一一个同声明资格谓词。这能在既有入口修复组合错误，避免增加 binding 逻辑或改变存储结构。只加 actor 检查不能阻止跨 sibling 拼接；仅移除关键词回退也不能解决两个集合判断分离，因此两者都需统一到单条 claim。

v2-v5 的原文启发式保留。来源预算、去重、归属车道、成员车道、渲染和公开 API 保持原契约。该修复不同时增加人物—话题—事件阶段排序，以便分离影响。

## 先测试后实现

- 两种写入顺序：“speaker 的 owns + 另一人的 prefers”不能作为 speaker 状态。
- 非状态 self claim 的原文含 now/after，不能通过词语绕过 family。
- 被拒绝的 self prefers + 有效 self knows 不能拼出有效状态。
- 正例：“speaker 的 prefers + 另一人的 knows”保留状态资格，两种写入顺序一致。
- 反向 SQLite 无序读取不改变最终结果；预算拒绝不能增加状态计数。
- v5 原文状态识别继续有效；既有来源隔离、回连与渲染回归通过。
