# SocialMemBench 原生两阶段证据回答设计

状态：按用户“大幅提升评测准确率”及持续自主迭代授权执行。顺序为中文设计、失败测试、C++实现、冻结开发评测与配对分析；本文件在新测试和实现之前写入。既有342份文档及容量父归档3526文件已核验并快照到`build/socialmem_evidence_checks/parent-documentation/`。不改评分、不读取旧298题保留集。

## 问题与方案

grounded_v1/512为已通过门槛的推荐开发配置，332/733。扩大容量到1024得到345/733，截断60→3，但增益区间跨零，未晋升。固定样本显示关键来源已经召回，仍出现发言人修辞误归属、反驳链遗漏和错误触发原因；仅提高输出上限不够。

备选方案：扩大检索可能补齐缺失锚点，但会同时改变输入且不能解释全锚点错误；直接强化提示成本低，但已有grounded与compact实验；本轮选择分开证据选择和最终回答，新增可复用的C++证据核验边界。预期提高已有证据利用率，实际增益由完整开发评测决定，不预先承诺达到高分。

## 原生接口与真实保证

新增`include/starling/retrieval/evidence_answer.hpp`及`src/retrieval/evidence_answer.cpp`：

- `source_evidence_prompt(question, source_block)`：解析已授权的SOURCE块，按原顺序赋予1起始的局部来源编号；保留speaker、session、turn_index、时间和原文，以JSON数据封装。只接收问题和召回块，不接收参考答案、题型、锚点或全历史。
- `verify_source_evidence(source_block, raw_plan)`：核验模型证据表，输出接受条目、拒绝原因和结构状态。每条必须有整数source_id、实际speaker、非空原文连续quote、解释interpretation；最多8条，解释为未验证模型推断。核验source_id范围、speaker精确匹配、quote是该来源文本子串。逐条拒绝错误，不将非法编号或引语替换成猜测值。JSON格式错误整体拒绝；允许外围单个json代码围栏，不搜索或拼接碎片。
- `evidence_answer_prompt(question, source_block, raw_plan)`：重新核验原始计划，给最终回答提供完整原召回块及通过引用核验的证据表。显式区分“引用/发言人核验”与“语义未验证”，要求检查旁白、主体、前态/触发/后态、反例及题干各部分。没有可用证据表时确定性退回原grounded_v1提示。
- `answer_with_evidence(question, source_block, LLMAdapter&)`：原生调用一次证据选择，再调用一次最终生成；返回两份原始LLMResponse、两份实际prompt、证据校验JSON及降级原因。绑定只暴露DTO和函数并释放GIL，Python不实现选择、引用校验或降级逻辑。

SOURCE输入须由ObserverRetriever完成租户、holder、时间与完整性过滤。新层不扩大来源，不按模型输出访问数据库。空问题在模型调用前拒绝；非法SOURCE行拒绝；空来源允许直接使用原grounded提示且跳过无意义规划调用。模型返回错误、截断、拒答、空内容或格式/引用全部不合格时仍保留原始失败回执，使用既有来源执行一次最终回答；这是预定义降级，不重试规划或选择性重跑。

核验只证明引用来自指定发言人和来源，不证明interpretation、被描述主体、因果角色或答案语义正确。不得把局部编号当持久statement_id，不写入事实库，不宣称补齐谓词、多阶心智或因果推理。所有LLM失败、降级与未知HTTP次数必须单列。
