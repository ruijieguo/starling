## 问题与目标

来源话轮真实归档已验证 163 个消息时间，但独立对象覆盖 9/14、主题与联合覆盖 1/14。Marcus 的五个候选全部因对象缺失主题/时间限定被拒绝。当前生成提示只要求泛化的上下文保留，没有明确说明 topic 必须为同源逐字短语并完整出现在 object；空字符串 topic、错误 nesting_depth 等还造成技术失败。本轮修复生成端与现有验证契约的描述偏差。

## 方案选择

采用 C++ 原生生成指导与通用中英文参考示例。参考示例只演示现有协议、主题选择、对象完整性、否定关系和相对时间，不能来自已冻结的 P1、synthetic、controls 或 Q1/Q9 内容。它们属于提示协议的一部分，与本次 SOURCE_DATA_JSON 独立编码。

自动拼接 topic/time 到返回对象会改变未经模型确认的命题；放宽同源文字校验需要新的证据表示与独立误收实验。因此两者留作独立设计，本轮保持原解析、准入、重试、存储和检索规则。

## C++ 职责与协议

`claim_extraction_prompt` 生成唯一模型提示，新增独立的 `REFERENCE_EXAMPLES_JSON` 区段。每例包含 source_holder、source、原生 source_units 和 response；示例 response 必须能被同一原生解析器接受，并且能通过原有入库/回读链路。示例在全部请求中固定，不能从用户正文、评测标签或历史响应生成。Python 只复用现有绑定、编排和统计，不新增语义逻辑或 prompt 副本。

生成指导明确如下：

- topic 选择来源 utterance 中逐字出现的简短主题短语，并保留在 object；同话轮的情绪对象、动作对象、原因和选项都可用作主题，不能用改写的主题代替逐字证据。正文无明确主题时使用 JSON null，不能使用空字符串或纯空白。跨话轮内容可帮助理解，但不能伪装为当前 clause_id 的逐字主题。
- object 保留情绪/动作、主题、原因、选项及所有 time_text 限定，保持原命题和语言。不能仅为满足字符串校验而把无关词强行拼入对象。
- time_text 使用原话中的限定词，包括 yet/仍未等状态时序；不能把 observed_at 转为 event_time。局部数据未提供绝对事件时间时保持 null。
- FIRST_PERSON 的 holder、subject、actor 使用实际 source_holder；nesting_depth 固定为整数 0，topic 可空，event_time 必填，输出单个完整 JSON 对象。
- 关系否定用 NEG 与 NEGATED；未决定可表达 POS 的 uncertain_about；决策对象的动作否定保留在 object。现有范围、归属与准入约束保持。

参考示例不构成训练标签、服务器 JSON Schema 能力或模型输出保证；参考内容不可作为当前声明证据。仍只允许一次抽取、一次有效候选准入，保留模型原文与技术失败。
