## 问题与方案选择

人物路由恢复了1082/1353个公开锚点。527题找齐锚点，其中308题仍未得分。开发机制诊断发现：漏答题干的证明要求、把邻近发言归给目标人物、把背景压力当作行为变化原因、把即时同意当作已有心智模型。锚点不穷尽答案，单次裁判存在误差，这些是可检验假设，不是对308题的完整归因。

比较三条路线：进一步扩大/重排检索可能增加干扰；结构抽取与关系推理是长期目标，但引入写入、词表、推理多个变化；先对回答政策做单变量试验可以检验现有证据的利用上限。本轮选择第三条，后续是否晋升由实际733题配对结果决定。

## 原生接口与边界

在现有`source_retriever.hpp/.cpp`增加纯函数：

```cpp
std::string grounded_source_answer_prompt(const std::string& question,
                                         const std::string& source_block);
```

函数只接收问题和已经授权、过滤、检索的来源块；不接收参考答案、锚点、题型标签、网络名称或完整历史。原文逐字保留，不总结、不增加事实，不作额外检索。空白问题抛出`std::invalid_argument`；空来源允许构造答题提示并要求承认信息不足。接口不会自行进行权限校验，调用者必须先执行ObserverRetriever。该接口是生成指导，不是确定性的事实/因果验证器。

C++统一生成通用提示：逐项覆盖题干；引用时绑定speaker、session与时间；区分自述、他人观察及推断；涉及变化时分别寻找前态、触发和后态，不能把时间相邻或背景因素自动当作原因；涉及他人认知时区分持有者和认知对象，不能把同意本身当成既有认知；提供必要短引语并解释与结论的联系，避免无关扩写；来源不足时明确局部不确定，不捏造。只返回直接答案及必要证据解释，不要求输出内部思维过程。

Python binding只导出函数；评测运行器新增显式`answer_policy=grounded_v1`，仅在`sources`模式的自由回答调用。默认`legacy`和全部选择题继续原提示；非法policy或不兼容模式在调用提供商前失败。不得在Python复制政策或检索逻辑。
