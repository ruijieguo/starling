# Dashboard 样例契约修复设计

当前样例脚本通过真实原生写入链路得到 26 条声明和 5 个承诺，但人物与关系均为零。根因是样例 FakeLLM 回答未包含 subject_kind；原生 JSON parser 对缺失类型安全默认 entity，Extractor 仅对明确的 cognizer 主体注册人物。

修复限于样例输入：已知人物明确给出 subject_kind=cognizer，自我主体补 cognizer_kind=self，其余人物为 human；发布计划和新服务明确为 entity。所有判断均为人工样例标签，C++ 仍负责解析、注册、写入和关系持久化。不改变生产解析默认值或以直接 SQL 插入补图。

先以真实 seed_demo 执行结果建立失败测试：八名具名人物齐全、两项非人物主体不会注册为人物、六条预设关系存在。同时验证声明、向量、gist 与四种承诺状态，防止修复社会图后破坏原有样例能力。测试使用临时数据库和 FakeLLM，不请求外部模型，不复用现有个人数据。

## 回归与运行验收

先执行样例契约失败测试，再修改样例 JSON。使用临时数据库验收人物、关系、承诺、向量和 gist。dashboard 重启采用当前安装的原生模块；原数据库保留并继续作为主服务的数据源，样例使用独立数据库、摄入队列及端口。API 与浏览器均须读取真实样例数据，不能仅以导航壳 smoke 代表数据正确。
