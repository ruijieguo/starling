## 证据与问题

2026-09-16 的 16 次真实能力探测均收到 HTTP 200 完整响应；D0 8/8 满足原生探测契约，D1 7/8。D1 的严格抽取逆格式探测返回 `assertion_scope="ASSERTED"`、`scope_markers=[]`。同一响应在 D0 和 D1 下均被拒绝，说明不是新增解析器差异。

`src/extractor/structured_output.cpp` 当前为 scope_markers 声明数组及元素枚举，没有最小长度或唯一性限制；本地 wire 校验也未检查这两个数组约束。C++ 声明契约另外要求非空、去重、主范围成员关系及合理组合。因此“wire schema 通过”和“来源契约通过”必须分开报告，不能把本次结果直接解释为提供商违反已发送的 JSON Schema。

## 建议的最小改动

1. 在 C++ 唯一 schema 生成器为 scope_markers 声明 `minItems=1`，并评估 `uniqueItems=true` 的端点兼容性；本地 wire 校验同步支持实际采用的数组限制。
2. 保留 C++ 中主范围必须属于标记集合、ASSERTED 与条件/问题范围不兼容、来源支持与归属等跨字段检查。不得自动补 ASSERTED，也不得为了提高探测通过率删除逆格式探测。
3. 现有五个谓词、候选字段、来源 proof 和生产默认保持。Python 仅负责 binding、模块/请求身份、归档与统计。
4. 新 schema 使用新的 hash 与新探测记录；不复用本轮 capability，也不将新 schema 与 R1/B 提示改动混为同一个因果比较。

## 文档、测试、实现顺序

先确认本方案并同步权威设计。随后新增 C++ 失败测试：空标记拒绝、重复标记拒绝、合法复合范围保留、主范围缺失拒绝；binding 验证实际加载新 schema hash；编排测试保证 wire 失败、原生解析失败、模型准入拒绝分别归档。最后实现 C++ 约束并运行聚焦及必要完整回归。
