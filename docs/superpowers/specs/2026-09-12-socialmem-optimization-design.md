## 目标

解决上一轮暴露的四类问题：情绪与认知判断混淆、职责陈述被误识别为信任、言语行为被错误标记为转述、跨话轮主题和原始时间丢失。优化必须保持旧 Statement 数据兼容，且生产核心逻辑全部位于 C++；Python 只做 binding、实验编排、归档和统计。

## 方案

### 1. C++ 关系和言语行为校验

`parse_claim_response` 在模型准入前执行确定性校验：

- `feels` 只接受情绪/感受及其主题；“feel/觉得 X 是真的”“确信归属”等认知判断进入 `wrong_relation`。
- `trusts` 必须有明确的信任对象和信任语义；`responsible for/负责/职责` 不能单独形成信任关系。
- `decided_on` 允许“已经接受/决定”的自我陈述；第一人称带 `said yes` 不自动变成 `REPORTED`，第三方转述仍必须带归属和 `REPORTED`。
- 保留条件、否定、疑问、转述等组合范围，禁止把条件后件提升为当前事实。

这些规则与现有谓词矩阵共用一个 C++ 实现，Bus、检索和 binding 不复制规则。

### 2. 原生 SourceTurn、主题和时间

来源单元仍由 C++ 按整行/整轮建立，但每个单元增加可选元数据：`speaker`、`session_id`、`turn_index`、`observed_at`。契约证据增加 `topic` 和 `source_turn`，其中 `source_turn` 保存原始会话、轮次和观察时间。元数据缺失时保持空值，不能用诊断观察时间伪造事件发生时间。

模型必须在对象中保留主题、指代对象、因果关系和相对时间词；C++ 验证主题和时间文本来自同一来源单元。检索 Context Pack 展示主题、说话者及时间依据；事件时间未知时标记 `UNKNOWN/source_time_fallback`。

### 3. 结构化输出和传输可靠性

准入和抽取继续采用单 JSON 值、禁止事后清洗的协议。C++ LLM 适配器增加结构化输出能力声明和传输错误分类：协议错误、语义拒绝、可重试传输错误分别记账。仅在服务端未收到请求或首字节前失败时进行有界重试；已产生字节的流式响应不得重放。Python 只读取 C++ 回执，不自行重试或解析协议。

### 4. 评价标签与裁判一致性

原 P1 标签和历史分数保持不变；新增 `topic`、`speech_act`、`scope`、`event_time` 扩展标签单独统计。相同候选和相同提示至少做双次裁判一致性控制，报告 Cohen κ/简单一致率；技术失败不计入语义分母。任何门槛失败都保持实验开关关闭。

## 数据流与边界

```text
原始 SourceTurn → C++ 单元索引/哈希 → LLM 候选
→ C++ schema/范围/关系/主题时间校验 → C++ 准入
→ Statement + semantic_claim_json → C++ tenant/perspective/topic 过滤
→ Context Pack/Receipt → Python 归档与统计
```

Python binding 只暴露字段、配置、回执和已有 C++ 方法；不得出现谓词语义判断、范围判断、主题拼接或传输重试实现。

## 兼容性与失败处理

- `semantic_claim_contract` 默认关闭；旧数组协议、旧 Statement 行和历史归档不可改写。
- 新字段均可空；旧行读取为空值并沿用原有检索路径。
- 来源、schema、范围、关系/主题时间和传输错误分别统计；任何技术失败不生成“成功但为空”的记录。
- 派生命题只保留父链，不继承直接来源证书。

## 测试和评测门槛

先新增失败测试并记录 RED，再实现 GREEN。C++ 测试覆盖关系误判、第一人称言语行为、SourceTurn 元数据、主题/时间同源性、结构化协议和重试边界；Python 测试只覆盖 binding 转发、回执完整性和统计一致性。

## 2026-09-12 JSON mode 请求实验设计

上一轮真实诊断有 8 个原生技术失败：主题空字符串 3 个、nesting_depth 类型 1 个、准入非法原因 3 个、JSON 后附解释 1 个。JSON mode 仅请求 JSON 对象格式，不保证 schema、枚举或语义正确，不足以解决全部失败。
