## 1. 问题与本阶段目标

S/T 已完成 84 次原生 HTTP 尝试、零重试。S1 没有达到推广条件；T120 只在所选样本中提高完整响应可达性。52 条原文已用各自冻结核心重放。本设计不改变这些结果，不把解析改善当作新的 F1。

已定位三个不同问题：

| 问题 | 已有证据 | 本阶段处理 |
|---|---|---|
| 无关问句误伤独立陈述 | Femi 的句首情绪声明被同话轮后续问号触发 QUESTIONED 拒绝 | L：保守的 C++ 声明范围定位及端到端本地回归 |
| 现有谓词内漏生成 | Marcus 两臂原始候选均缺未决、决定、情绪信息 | R0：原始候选与各处理阶段的可核对索引、离线覆盖表 |
| 关系误分类、目标/时间不完整 | 认知信息误标 feels；objecting 丢失反对目标 | 作为独立关系边界 B 的后续输入，本次不改谓词或提示 |

L 的首个交付有意限定为**能够逐字定位的句首直接陈述**。后面的决定、跨句声明、抽象改写或仅有 topic 的候选仍可能保守拒绝；例如 Femi 另一个话轮里的订路权决定，不是本阶段必须恢复的案例。这个边界用于先验证范围修复，不承诺解决任意自然语言依赖。

## 2. 方案比较与选择

| 方案 | 优点 | 代价与风险 | 决策 |
|---|---|---|---|
| v2 内 C++ 保守定位，局部化 QUESTIONED | 不要求模型新增字段；原始回执可直接重放；存储和检索可复用同一规则 | 逐字锚点和受限句首结构覆盖有限；不能证明语义蕴含 | **本阶段采用** |
| 新版协议显式输出支撑文本、依赖来源 | 更适合改写、多片段和跨句依赖，可表达模型选择的证据 | 模型仍可能裁掉条件；需要 schema、能力探测、来源校验及兼容性升级，增加已有字段失败负担 | 独立后继设计；本次不创建 v3 |
| 取消原生问号守卫，全部交准入 | 实现简单、减少一类误拒 | 真实疑问全部通过确定性层；存储侧重放不能执行模型准入，校验边界变化过大 | 不采用 |

本方案只改变 QUESTIONED 的检查输入。CONDITIONAL、HYPOTHETICAL、REPORTED、NEGATED、主体归属、关系类型、主题和时间等继续使用原有规则和完整来源。模型准入仍读取完整 payload 和整条 source unit；它不能补写候选，也不能把文本定位当成语义证明。

  B --> C[C++ 范围定位]

`parse_claim_response` 是抽取、直接写入验证及检索证据重放的共同规则入口。`src/retrieval/claim_evidence.cpp` 已调用此函数，不新增另一份定位实现。Python 只接收原生诊断、组织离线回放和统计；不实现分句、词表、语义匹配、schema 校验或字段修补。

## 4. L：定位契约

### 4.1 来源坐标

`clause_id` 仍是现有非空整行/整话轮编号。`source_span` 仍覆盖该整单元在原始 payload 中的 UTF-8 字节范围，`source_hash` 仍是完整原始 payload 哈希。不得重编号，不将新局部范围写成持久化来源证明。

定位输入必须与原守卫一致：有 `utterance` 时取解码后的 utterance，否则取 source unit 的 `text`。诊断中的 `[begin,end)` 是这一输入的 UTF-8 **字节**偏移，分别标记 `utterance_utf8` 或 `source_unit_text_utf8`。它不是 Unicode 字符索引。

版本化 SourceTurn 的 JSON 转义、嵌入换行及 UTF-8 长度会改变外层坐标；禁止把局部偏移直接加到 JSON 行的 payload 起点。诊断只提供局部坐标及 `clause_id`、payload hash，消费者通过同一来源清单解释；不生成未经验证的 payload 局部链接。

### 4.2 唯一完整锚点

没有问号的输入直接返回 `whole_unit/no_question`。有问号时，只有已通过全批结构校验、holder/actor/来源 speaker 相符的 FIRST_PERSON、POS、`scope_markers=[ASSERTED]` 候选可尝试局部化。其余均使用整单元。

完整 `object` 必须在守卫输入中**逐字、连续、唯一**出现，且完整落在句首第一个明确陈述范围内。匹配不改大小写、不归一化 Unicode、不重排词语、不删除否定或标点；短语前后若是同一 ASCII 词的一部分则不是有效匹配。抽象 object、重复锚点、跨句 object、仅有 topic 命中都回退。大小写不同造成的保守回退可以接受，不为提高恢复率补充模糊匹配。

topic、time_text 和 event_time 若非空，还须按原契约校验，并位于这个陈述范围；它们只约束完整性，不能代替 object 定位。单独的代词/指示词 object（如 it、that、either way、这、那个）不作为局部化依据。它们的原有语义处理不受影响。

### 4.3 受限句首范围

范围从守卫输入的第一个非空白字节开始，到第一个无歧义陈述终止符结束，包含终止符。普通 `Name:` 来源允许识别并跳过与已验证 speaker 相同的前缀；诊断偏移仍相对原守卫输入。typed utterance 不剥除名字，不修改原文。

明确终止符为 `.`、`!`、`。`、`！`。ASCII 句号须后接空白或输入结束。以下情况不得据此局部化：

- 首个范围内出现 `?` 或 `？`，或首个结束符是问号。
- 首个范围前出现内嵌换行，或 object 跨越范围边界。
- 引号、括号、代码围栏或非 speaker 的冒号导致嵌套/列举/转述歧义；弯引号也属于引号。ASCII 单引号两侧均为字母时可作为缩写中的撇号，例如 I'm，其余按引号处理。
- 小数、网址、邮箱、缩写句点或省略号可能被误当句界。首期保守回退，尤其覆盖 Mr./Mrs./Ms./Dr./Prof./Sr./Jr./St./vs./etc./e.g./i.e. 和单字母首字母缩写；不宣称完成通用句子切分。
- 候选范围是问句、条件、假设、引用开头或依赖前文的片段。原有 if/unless/如果/假设等整话轮守卫继续有效。

未落在句首范围的候选一律回退。不能通过先丢弃前文，再把中间某句当作新的句首获得资格。

### 4.4 后续问句与依赖风险

从首个陈述终止符之后顺序扫描后文，沿用上述无歧义分界要求；每个问号都必须属于一个完整问句。其他闭合陈述可以跳过，但仍参加整话轮依赖风险检查；非空未终止尾文（包括省略问句）直接回退 `ambiguous_boundary`；不能仅取出其中一个看似无关的问句而忽略其余问号。

只识别少量容易检查的后续完整问句形式：英文以 `Do you`、`Can you`、`Could you`、`Will you`、`Would you` 开头、至少含三个词并以问号闭合；中文以 `请问` 开头并以全角或半角问号闭合。比较这些语法词可做 ASCII 大小写折叠，仍不得改变来源偏移。未识别形式回退；不通过缺少问号推断真实世界断言。

以下情况即使 object 唯一命中也回退：

| 风险 | 首期保守判据 |
|---|---|
| 问句回指声明 | 问句含第一人称单数 I/me/my/mine/myself、指示/回指词 it/this/that/these/those/them/so，或中文 我/这/那/上述/刚才/如此 |
| 问句重复声明内容 | 问句重复完整 object/topic，或共享 object 的英文实词片段（连续 ASCII 字母至少 4 位）/连续两个汉字；这是保守碰撞检查，不是相似度模型 |
| 反问、附加问句、撤回 | `Or am I?`、`really?`、`right?`、`isn't it?`、`是吗`、`真的吗`、`对吗`等；后文出现 joking/kidding/just imagining/不是认真的/开玩笑/更正/撤回 |
| 条件、假设、转述或否定依赖 | 既有显式条件/假设触发；引号/括号；said/says/reported/according to/据说/表示；not/never/n't/不/没/无等否定提示时保守回退 |
| 分界不明 | 问号不能归入闭合的受支持问句、连续问号或省略片段、嵌套标点 |

英文风险词按词边界匹配；中文按原文片段匹配。这些检查宁可增加回退，也不改原候选。实现不得根据 benchmark ID、人物、地点或具体答案选路。除上述有限规则外，不新增“语义独立性评分”或伪造置信度。

**限制：** 满足这些规则表示通过受限文本检查，不表示已证明任意语境下独立。语言中的讽刺、隐含撤回及语用依赖仍由完整原文准入判断。直写和检索的确定性重放也不构成模型准入证明；本设计不扩大它们原有的可信度声明。若负例发现误放，先收紧该模式或整体回退，不边跑真实评测边增加特例。

### 4.5 使用与失败粒度

定位输出是 `whole_unit` 或 `leading_statement`，附稳定 reason 及可空局部范围。whole_unit 时问号检查逐字沿用旧输入；leading_statement 时只对局部范围检查 QUESTIONED。**所有其他守卫仍收到完整输入**。

找不到唯一锚点或存在依赖歧义本身不产生新的拒绝类别，而是返回旧守卫。真实 QUESTIONED 候选照旧校验其主作用域、标记和 modality；禁止自动补 marker、把 ASSERTED 改成 QUESTIONED 或删除原文问号。

结构错误仍整批拒绝并清空行结果；行级语义错误仍只拒对应行。合法空候选不变。局部化不改候选内容、顺序、source_span、来源 hash 或持久化 evidence schema_version=1。

## 5. R0：可核对的原生行诊断

现有 `semantic_rejections.index` 指向原始响应，而准入 `decisions.index` 指向解析保留后的数组；重复候选不能靠 object 文本反向匹配。C++ 新增每个已完成结构校验行的诊断：

| 字段 | 含义 |
|---|---|
| `index` | 原始 statements 的零基索引 |
| `candidate_index` | 解析保留数组中的索引；语义拒绝为 null，准入后不重编号 |
| `outcome` | `candidate` 或 `semantic_rejected` |
| `scope_resolution` | 未执行范围守卫时为 null；否则含 mode/reason/coordinate_space/begin/end/clause_id |

`ClaimParseResult` 和 `ExtractionLlmAttempt` 保留该诊断；导出的解析 JSON 及抽取 receipt 增加 `row_diagnostics_schema_version=1` 与 `row_diagnostics`。这些是可选诊断扩展，**不进入模型请求、准入 candidates、SemanticClaimEvidence 或数据库**。whole_unit 的 begin/end 为 null；不会把整话轮偏移伪装成局部锚点。

结构失败时诊断数组为空，不把未执行的行伪标成语义成功。准入失败仍保留准入前索引及原始响应，最终保留数组按既有语义输出。旧回执没有此扩展时标记诊断未知；可另存新核心的派生重放结果，不能回填旧档案。

离线覆盖表以 `(原回执 SHA-256, 原始行 index)` 关联；来源按 holder/clause_id/hash 定位。对人工阅读确认的状态，单独记录原始候选匹配索引及理由，不用 Python 关键词程序生成关系标签。阶段分为：

1. 来源中是否有可由现有谓词表达的状态：人工来源判断，标注不确定性。
2. 完整原文中是否生成候选：只有完整且可审阅的响应才可记“未生成”；超时/损坏输出为未知。
3. 全批结构拒绝、行级来源语义拒绝、解析候选分别记录。
4. 准入、入库、检索是否实际执行；未运行一律记“未执行”，不能推断为遗漏。

S/T 原来没有准入、入库、检索、QA 或 judging。因此本阶段只能填到解析，并分析目标/时间是否保留。Marcus 的生成遗漏不会被 L 修复；固定原文回放中的生成候选数必须保持不变。
