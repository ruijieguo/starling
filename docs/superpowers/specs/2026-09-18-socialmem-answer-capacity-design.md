# SocialMemBench回答容量单变量设计

状态：按用户持续授权及本轮“继续”完成执行；下文保留事前设计，末节记录实测结论。顺序为中文文档、失败测试、编排实现和完整真实评测。实验前推荐开发政策为grounded_v1，332/733＝45.29%；紧凑政策248/733＝33.83%未晋升。两个父归档及339份最终文档已核验并快照。

## 问题与选择

grounded_v1在512-token预算下有60题截断、1次回答传输失败、13次裁判超时。紧凑政策消除了截断，却使原正常题净减88，说明不能继续把统一缩短回答当作质量优化。下一步首先隔离输出容量，再决定是否投入更复杂的证据表示。

可选方案为扩大单次回答预算、截断后续写、重构时间/因果证据。本轮只选第一项：回答max_tokens从512改为1024，其余保持父政策。续写会增加请求及上下文状态，证据重构会改变输入，均另行设计。此轮是容量诊断，不将增加计算预算称为C++推理能力提升。

## 原生实现边界

直接复制父实验冻结的全部代码和C++核心，不使用当前工作区的紧凑核心，不重编译或复制语义逻辑到Python。原有Python binding将配置传给C++ OpenAIAdapter；本轮只新增冻结编排和离线统计。所有733题使用父grounded_v1原提示；来源block、refs、原生排序及模型逐题保持。

既有运行器共用answer_max_tokens，因此152道选择题也收到1024上限；其提示与评分不变，但不能称请求完全相同。选择题结果波动单列。配置仅允许answer_max_tokens=1024，不允许同时修改核心、裁判、thinking、超时、workers、k、字节预算、重试或添加额外配置。
