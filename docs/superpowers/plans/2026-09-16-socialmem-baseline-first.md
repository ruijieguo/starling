## 执行顺序

1. 冻结当前工作树的 C++ 核心、Python binding/package、通用评测脚本、数据及提示；在隔离副本跑当前默认 Starling 的全部1031题。基线完成前不修改被测源码、schema、提示、检索或生产开关。
2. 分题型记录分数，保留失败分母和逐题上下文。先获得实际成绩，再分析失分位置；新测试和方案由真实失分驱动。
3. 每轮先中文设计，再失败测试，再 C++ 实现。按固定题集、模型、评分和预算复测，报告增加/减少的正确题及配对差值。无收益的候选不替换当前最佳版本。
4. 继续下一轮最高优先级缺口；每轮有独立冻结与有界调用，不把自主迭代理解为无上限重复请求。保留网络在候选确认前只报告汇总，不用于查看答案后逐题调参。
